# Noridoc: tests/e2e

Path: @/tests/e2e

### Overview

- **The acceptance layer (E6).** Playwright specs that drive the **real app in fixture mode** through the browser — login → Setup → the listener stations → Dashboard — proving the end-to-end product criteria of @/docs/plano-de-acao-mvp.md §3 and @/docs/PRD-colar-de-sons-v2.md §9. Since ENG-689 (scope cut 1/4) the cycle these specs walk ENDS at Frases: no conversation, no report, no export, and no artifact is ever produced by the running app — the last productive scene closing is what ends a session, and what survives it is the autosaved `SessionState`.
- Distinct from @/tests/golden: the golden harness proves `domain ≡ reference` by byte-diffing artifacts against the untouchable v1 reference; these specs prove the **assembled UI + adapters** deliver those artifacts and the ear-first behavior through actual DOM interaction.
- Runs as the CI job `e2e` (@/.github/workflows/ci.yml) via `pnpm e2e`. It is an **additional, non-required** check (CLAUDE.md quality gates) — the golden harness remains the only unrelaxable gate.
- **Local runs on macOS: use `pnpm e2e:awake`.** With the display ASLEEP (overnight/lid dimmed), Chromium's input acks ride the frame-presentation pipeline and flush only on a ~15 s watchdog — every click stalls to the next 15 s boundary and any spec longer than ~15 s times out (ENG-330; measured: in-page `pointerdown` lands instantly, only the CDP ack waits). `caffeinate -u` wakes and holds the display for the duration of the run. CI (Linux) is unaffected.

### How it fits into the larger codebase

- Exercises every outer layer at once through @/ui (pages/app wiring) → @/adapters in **fixture mode** → @/contracts → @/domain, with no real API/audio/network. The fixtures under @/fixtures (esp. the bucket audio's `PcmSpec`) are what let the app boot offline.
- Reads persisted session state straight from `localStorage` — the key belongs to `FixtureSessionBackend` (@/adapters/sessions) and the autosave path documented in @/docs/PRD-colar-de-sons-v2.md §7.3 — to assert zero-loss and completion status without trusting a self-reported flag.
- Depends on the audio Player wiring in @/ui/app: the fixture player's rAF-driven playhead lights `data-play` on `.cds-necklace-bead`, which the specs treat as the DOM-observable "sound" signal.

### Core Implementation

```
playwright.config.ts ──webServer──> vite (SPA fallback, real app, fixture adapters)
        │ testDir tests/e2e, chromium headless, reducedMotion=reduce, workers=1
        ▼
  *.spec.ts ──imports──> support/  (ColarApp page object · SCENARIO · read* helpers)
```

- @/playwright.config.ts boots Vite as its `webServer` (SPA fallback so History-API routes resolve), pins a single Chromium worker, and forces `prefers-reduced-motion: reduce` so geometry-based bead clicks never race an animation. Vitest never sees these specs — they live outside its unit/dom/browser globs.
- @/tests/e2e/support (barrel @/tests/e2e/support/index.ts) is the shared driver, imported read-only by every spec:
  - `ColarApp` — a page object with one method per station step: `login`, `createSession`, `clickBead`, `confirmWholeStory`, `cutScenes`, `triage`, `passBlockDone`, `cutPhrase`, `moveSeam`, `nextScene`, `finishPhrases`, `leaveAfterPhrases`. Every selector is verbatim PT-BR copy from the stations, so a copy change fails here at a single point instead of across specs. Since ENG-279 that copy lives in @/ui/i18n/pt.ts and PT is only the DEFAULT language: the specs never touch the header's PT/EN toggle and never seed the `lang` localStorage key, so the app boots in PT and the selectors hold. Editing a PT dictionary value breaks these specs by design.
  - **Two steps in the flow end on a full-screen dialog** (ENG-651): `triage` and `finishPhrases` each close a _block_, so after the confirming click the block-done screen covers the station that was just reached. `triage` ends with `passBlockDone('Seguir para as frases')`, which clicks that screen's primary and lands on Frases. `finishPhrases` closes the SECOND block — the one that now ends the whole flow (ENG-689) — and asserts its headline directly instead of clicking through, because that screen's only remaining exit is a separate helper: `leaveAfterPhrases()` clicks "Voltar às histórias" and asserts the dashboard is back. **The screen renders in a Radix portal, outside `main.cds-app-main`** — @/tests/e2e/minimalism.spec.ts therefore points `scanListenerSurface` at `.cds-block-done` itself, because scanning `main` there would silently measure the station behind it and pass for the wrong reason.
  - **The inferred review moment (design parity, @/ui/pages/cut, @/ui/pages/triage, @/ui/pages/phrases) means the PRD CTA is conditional.** `cutScenes`, `triage`, `nextScene` and `finishPhrases` each probe for a "Continuar →" button first and only fall back to the PRD's own copy ("Confirmar as cenas →", "Já classifiquei todas as cenas →", "Pronto com esta cena →", "Já segmentei todas as cenas →") when it isn't there — so `SCENARIO`'s fully-covered runs exercise the review path while a caller building a sparse/partial scenario still gets the PRD button. `triage` always lands on "Continuar →" because `SCENARIO` classifies every locked scene.
  - `SCENARIO` — a deterministic decision script over the `conto-do-boto` fixture audio that mirrors the golden `seam-small-move` case (three scenes, one `none_fit`, a border-crossing phrase whose seam slides).
  - `readPersistedState` — pulls the autosaved session DTO out of `localStorage`, for zero-loss assertions across a reload. `readPersistedStatus` and the interview's `TYPED_ANSWER` fixture left with the interview stations in ENG-689.
- Each spec targets one acceptance criterion — the full listener cycle across sittings (now ending at Frases, not at Export), the oral-mode behavior, layout at short viewport heights, and mid-session **resilience** (connection drop, auth expiry, advisory lock) — composing `ColarApp` for the shared path and adding its own assertions. The artifact **byte-identity** and Dashboard-artifact-retrieval specs (`contract-identity.spec.ts`, `dashboard-retrieval.spec.ts`) were deleted in ENG-689: there is no artifact for the UI to produce or retrieve any more, and the golden harness (@/tests/golden) still proves `domain`+`contracts` produce byte-identical artifacts on their own, with no UI in the loop.

- @/tests/e2e/design-capture.spec.ts is a **manual visual-parity tool, not a test**: `test.skip(!process.env.CDS_CAPTURE, ...)` means the whole spec is skipped unless run with `CDS_CAPTURE=1` (CI never sets it, so this spec never runs there). It walks `ColarApp` through every station and screenshots each one to `.parity-shots/` (gitignored) for a human to eyeball against `docs/design/Colar de Sons - Protótipo.dc.html` — there is no pixel-diff assertion, because the point is human review of the CLAUDE.md precedence-rule-2 realignment, not a regression gate.

### Things to Know

- The oral-mode spec (@/tests/e2e/oral-mode.spec.ts) installs a DOM spy via `page.addInitScript` (`window.__oral`): a `MutationObserver` records ordered `sound` events (a bead gaining `data-play`) vs `text` events (new non-empty text outside `.cds-necklace`), and capture-phase click/focus listeners flag any interaction reaching chrome (`.cds-header`/`.cds-story-progress`, a single `CHROME` constant shared by the probe and the spec). It asserts sound-before-text at the DOM-observable ear-first decision points, that an edge-dwell nudge plays without changing the selection bands, zero chrome interaction across the listener path — first proving the chrome selector actually matches something, so a renamed or retired class (ENG-668 took `.cds-stepper`) cannot quietly turn that into an assertion about nothing — and non-text signifiers (`aria-hidden` text-free beads, `data-role` on instruction/primary-action). Where playback is **not** DOM-observable (a selection-completing tap whose confirm renders before the playhead lights) the property is proven by the control's non-textual signal and in-station advance instead.
- Ear-first is enforced as an ordering invariant, not a timing one: assertions poll for the first `sound` event and only require `firstSound < firstText` when text appears at all.
- The short-window spec (@/tests/e2e/short-window.spec.ts) is the only one that leaves the suite's 1280×900 viewport: it replays the Triage station at 900, 800, 700 and 620px tall, because a layout bug that a comfortable window hides is exactly the one that ships. It asserts three things per height — at least 6 kind cards **fully inside** the grid's scroll box, no overlap between the coverage drawer's floating tab and any card, and that `elementFromPoint` at the centre of "Confirmar" lands inside the button. That last one exists because `toBeVisible()` cannot see clipping or overlap, and `.click()` auto-scrolls before it acts: both passed happily while the confirm button was sealed under a 53px scroll gap. One height would not do — the previous fix (PR #164) closed 700 and left 620 broken.
- The resilience spec (@/tests/e2e/resilience.spec.ts) drives the three failure triggers the runtime handles, each with a distinct entry point: **connection drop** needs no seam — `page.context().setOffline(true)` makes Chromium fire the window `offline` event that `useOnline` in @/ui/app reflects into `.cds-connection-gate[data-offline="true"]` (PT-BR `Sem conexão` warning), sealing edits while already-loaded playback keeps ticking; **auth expiry** and **foreign lock** are provoked through the DEV-only `window.__cds` seam (@/ui/app `test-seam.ts`, installed only under `import.meta.env.DEV`, which the Vite dev `webServer` satisfies) — `expireAuth()` routes to `/login` and `seedForeignLock(id)` writes Ana's lock into the same `FixtureSessionBackend` so a `page.reload()` re-hydrates into review-only mode (`sessão em uso por Ana`, no "Destravar para editar").
- Two resilience proof gotchas for future authors: the confirm controls (`✓ Confirmar esta cena/frase`) render whenever an anchor is active, so **"no confirm button" is not a blocked-editing proof** — assert no locked chip is born and the persisted DTO is deep-equal unchanged instead; and `data-play` lighting is **cumulative**, so proving playback _continues_ while offline tracks the moving `[data-play="head"]` playhead index (a `.first()` match or a static "still lit" check cannot tell playing from frozen).

# Noridoc: domain

Path: @/domain

### Overview

- The **frozen core**: pure TypeScript, zero imports (no other layer, no npm packages), a 1:1 behavioral port of the v1 reference at @/docs/reference/index.html.
- Modules land in dependency order via the E1 issues, all re-exported through the @/domain/index.ts barrel (which also keeps the `DOMAIN_LAYER` marker). Landed: ENG-214 — bead grid math (@/domain/grid.ts), FNV-1a `manifest_id` hash (@/domain/hash.ts), lowest-free ID allocators (@/domain/ids.ts); ENG-216 — session state (@/domain/state.ts), frontier/active anchor (@/domain/frontier.ts), the bead-click selection model (@/domain/selection.ts), and whole-story + sequential scene cutting (@/domain/scenes.ts); ENG-219 — the generated Ruth scene-kind ontology (@/domain/scene-kinds.ts), the triagem picker mutations + selectors (@/domain/triagem.ts), the coverage derivation (@/domain/coverage.ts), and the mode gates (@/domain/gates.ts); ENG-223 — the phrase lifecycle (@/domain/phrases.ts) and the seam/border-crossing logic (@/domain/seam.ts). **ENG-226 added the interview's verbatim mapeamento question scripts (`domain/mapeamento-scripts.ts`) and the lazy answer store (`domain/mapping.ts`), completing the E1 domain chain — and ENG-691 (scope cut 2/4, owner decision 2026-09-01) removed both** when the interview left the product; the chain now ends at ENG-223.
- Exists as its own layer so the entire rule set compiles and tests with no framework/IO. Until ENG-691 this also made byte-identical artifact reproduction provable by the golden harness (@/tests/golden); that harness and the artifacts it proved are gone (see Things to Know) — `domain/`'s own unit tests are now the only proof the port still matches the reference.

### How it fits into the larger codebase

- Innermost layer of `ui → adapters → contracts → domain`. The zero-import rule is mechanical, not conventional: @/.dependency-cruiser.cjs errors on any import of another layer **and** on any npm package from production code (tests may import vitest).
- Consumed by: @/contracts (DTO mappers over domain types), @/adapters, `ui/organisms` and `ui/state` (domain types/state via props/hooks — see @/ui/docs.md).
- **The golden harness is gone (ENG-691).** It used to replay scripted decision sets through `domain/` + `contracts/` and byte-diff the artifacts against goldens generated from the reference, proving `domain ≡ reference` on every PR — the reason the layer was frozen. It was removed outright, together with the three artifacts it diffed, when the owner decided the app would stop producing them (keeping the JSON builders alive purely to keep the gate alive was considered and rejected). The layer stays frozen — `contract-critical`, human review required on every PR — but that review is now the _only_ thing standing there; `domain/`'s own unit tests are the only remaining proof against @/docs/reference/index.html, and they are the port checking itself, with no second source. See @/CLAUDE.md's "The golden harness is gone" section.
- Effects are values, never side effects: reducers return new state (plus a `PlayAction` in @/domain/selection.ts and the `BorderOffer` in @/domain/seam.ts); the interpreters — audio playback, border-offer dialogs — live in @/adapters and the UI wiring layers, and UI organisms consume state via props/hooks only.

### Core Implementation

- @/domain/grid.ts — `buildBeads` (grid = `floor(dur/beadSec + 1e-9)` beads plus a partial bead when a remainder > 1e-9 exists; every `startTime`/`endTime` is coerced through `+(x).toFixed(6)` and `endTime` is clamped to the duration), `beadAtTime` (time → clamped bead index, same epsilon), `spanDur` (span duration from bead times; throws on out-of-grid indices — a `noUncheckedIndexedAccess`-driven guard).
- @/domain/hash.ts — `PcmLike` (the minimal AudioBuffer-shaped interface: channels, sampleRate, `getChannelData`) + `hashPCM`, the FNV-1a 32-bit `manifest_id` (`fnv1a32:xxxxxxxx`). Byte-mix order is contract: channel count, the 2 low bytes of sampleRate, sample count as 4 bytes LE, strided int16-quantized samples from channel 0 (stride = `max(1, floor(N/100000))`), then `beadSec*1000` as 3 bytes LE.
- @/domain/ids.ts — `nextPartId` (`PT#`) and `nextPid` (`P#`): lowest free number, scanning ALL entries — locked or not, because pending slots occupy their ID.
- @/domain/state.ts — the COMPLETE `SessionState` shape (whole/parts/frases/current/activeSceneId/selection/pendingStart/mode/review plus the audio facts: duration, beadSec, bead grid, `manifest_id`, filename, slug) and `createSession`, mirroring the reference's `state` object (reference L367–379) and the reset done by `segment()` (L454–462). Later issues only ADD functions over this shape — they never edit the state module, with one registered exception: ENG-691's scope cut REMOVED the `mapping` field and the `mapeamento` mode value from this file when the interview left the product (a change to the shape, not an addition). UI/playback fields of the reference (`color`, `beadSize`, `paused`, download flags, `audioBuffer`) are deliberately excluded: they belong to @/ui and @/adapters.
- @/domain/frontier.ts — `frontier(state, layer)`, the COMPLETE frontier of both layers, and `activeAnchor` (the current unlocked item, if any, with its frontier as anchored start). On the phrase layer with a productive scene in focus it runs the active-scene branch first: last locked phrase end in that scene + 1; with no phrase in the scene, back-reach to the START of the previous locked neighbor (via `prevNeighbor` from @/domain/seam.ts), else the scene's own start — and this branch returns BEFORE the clamp. Only when no productive scene is in focus does it fall to the generic branch (max locked end + 1, capped at the last bead; the phrase layer floors at `whole.span.s`). Housing the full branch here (rather than only in @/domain/phrases.ts) is what makes `activeAnchor().start` — and therefore the `clickBead` clamp in @/domain/selection.ts — honor back-reach; the earlier split left clicks floored at 0 before the first phrase.
- @/domain/selection.ts — `clickBead`, the DEFINING click model (owner decisions, 2026-08-07; @/docs/segmentation-rules.md rule 1). Three beats: no selection → mark the START there and let the audio RUN from it (`run`, the UI plays to the parent end); `pendingStart` set → close the stretch (`set-end`; the UI stops only if the playhead already passed the marked end, else it does not interrupt); stretch closed → move the NEAREST boundary, ties to the start (`<=`). That last branch splits by whether the boundary actually moved: it did → `adjust`, which carries `delta` — the stretch that changed hands, from the boundary's old position to its new one (the UI leaves running audio alone while the playhead is INSIDE the resulting stretch, and otherwise plays that delta: growing gives back what the scene gained, shrinking what it lost); it did not (tapping the start or end bead where it already sits) → `range`, replaying the whole stretch, standing in for the reference's `playSel` button that ENG-291 removed. The click is clamped between `activeAnchor().start` and `whole.span.e`. There is no pre-anchoring: `addPart`/`addFrase` open the slot with `selection: null`, so the start comes from the first click — which also means an ACCIDENTAL gap between scenes is now possible.
- @/domain/scenes.ts — whole-story confirm and the sequential scene-cutting reducers (`addPart`/`primePart`/`confirmPart`/`confirmParts`, reference L685–767 and `enterLayer('parts')` L930–935). All reopen (whole L677–680 and scene L726–731) was removed in ENG-342 — a locked scene is adjusted by dragging its boundary (`dragSceneBoundary`, @/domain/seam.ts) or removed with `removePart` (mirror of `removeFrase`; not in the reference, added to give scenes the phrase's post-hoc removal). Both `removePart` and `removeFrase` stay pure/reference-faithful; the owner-approved "next item absorbs the freed gap" (#3) is a SEPARATE pure step — `absorbNextScene` / `absorbNextFrase` — that the station composes AFTER the remove (like the post-drag re-anchor). Until ENG-691 both distinctions were also stated in golden-harness terms — replayed directly vs. composed outside its byte-identity scope; that harness is gone, so the distinction stands purely on which function is the reference-faithful reducer and which is UI composition. The story is un-confirmed via the Cortar back action (`setMode('escuta')` + `whole.confirmed=false`), not a reducer here. Validation failures return a typed `Result` (`{ok:false, error:{code, message}}`) whose PT-BR messages are contractual copy exported as `SCENE_ERROR_COPY` — the UI must reuse them, never rephrase. `confirmParts` prunes unlocked slots and transitions `mode` to `triagem` directly (the mode gates proper live in @/domain/gates.ts).
- @/domain/scene-kinds.ts — the generated 27-kind Ruth ontology (`SCENE_KINDS`, tier + verbatim order from `_spec/scene-kind-palette.json`, pin 5314907 — never hand-edit). Each kind's English `value` IS the Compilador contract and is exported as-is; `SK_PT` holds PT-BR display labels (display-only, never stored) and `skEnShort`/`skShort` produce the short display labels @/ui/i18n/scene-kind-label.ts resolves (ENG-233; the report `.md` these once also fed was removed in ENG-691, see @/contracts/docs.md). `T_TARGET` is the per-tier coverage target (ALTA=1, comum=3).
- @/domain/triagem.ts — the picker: mutations `tagScene` (sets `tag_state='tagged'` + `scene_kind` + confidence) and `markNoneFit` (`tag_state='none_fit'`, nulls kind/confidence), plus selectors `lockedParts` (locked && span) and `productiveScenes` (locked && span && tagged, in parts order). Pure immutable maps keyed by `part_id`; no throw.
- @/domain/coverage.ts — `computeCoverage`, a pure port of the reference's `renderCoverage` calc with its DOM side effects and its `updateModeLocks`/`updateTriagemDone` calls stripped (those are now pure in @/domain/gates.ts). Firm = alta|média, hesitant = baixa; per-kind status covered/partial/open; `candidateAbsence` = tier ALTA && firm===0 (the reference's open-rara predicate — ignores hesitant); `allNoneFit` lockout = every locked scene triaged && zero productive. Also exposes additive aggregate derivations (total, rare totals, noneFit, productive, triaged) for the ENG-225 coverage drawer.
- @/domain/gates.ts — the mode gates + triagem hard gate as pure functions: `triagemDone` (enabled iff every locked scene is non-pending && ≥1 productive; its PT-BR helper copy is contract-level, verbatim incl. curly quotes/em dash), `modeLocks` (escuta always; triagem⇔`partsConfirmed`; segmentacao⇔productive>0 — this is the LAST key: `ModeLocks` had a stricter `mapeamento` key, productive>0 && ≥1 locked phrase with span, that ENG-691 removed along with the mode, since `concluida` is the end of the flow and not a tab to gate), `resolveMode` (the setMode redirect — segmentacao **or `concluida`** with zero productive fall back to triagem; it checks ONLY productive, not phrases), and `setMode` (applies `resolveMode`, always drops `review`, and sets `partsConfirmed=true` when entering segmentacao with locked parts — the reference L1005 side effect).
- @/domain/seam.ts — the seam between scenes, all pure data: `activeScene` (the productive scene in focus: resolves by `activeSceneId`, else the first productive from @/domain/triagem.ts — it lives HERE, not in @/domain/phrases.ts, so @/domain/frontier.ts can import it without a cycle), `prevNeighbor`/`nextNeighbor` (nearest LOCKED neighbors — none_fit counts; they return `AnchoredPart`, span proven in the type), `sceneHasFrases`, `classifyBorderMove` (the border-crossing offer as a `BorderOffer` value — kinds `simple`/`escalation`/`two-productive`, threshold `max(3, round(0.25·span))`, `consumed` = the selection swallows the whole neighbor, `canMove`, contractual PT-BR copy in `BORDER_COPY`; throws on a productive scene without span/kind — caller-invariant violation, not flow), `slideSeam` (the scene grows, the immediate locked neighbor shrinks; immutable, untouched parts keep identity), and the segmentação render window `windowMargin`/`sceneWindow` (`max(3, round(2/beadSec))`).
- @/domain/phrases.ts — the phrase lifecycle over the productive-scene view of @/domain/triagem.ts: `sceneIndexOf`, plus `activeScene` re-exported from @/domain/seam.ts and `phraseFrontier` as a pure alias of `frontier(state,'frases')` in @/domain/frontier.ts (both kept so the @/domain/index.ts public API stayed stable when the logic moved), `addFrase` (lowest free `P#` via @/domain/ids.ts; no-op while an anchor is active), `confirmFrase` (guards in the reference's exact order, returning a discriminated `locked`/`border`/`noop`/`error` union with contractual copy in `FRASE_ERROR_COPY`; a border crossing returns the `BorderOffer` — the UI decides), `moveBorder` (slide the seam then lock), `reanchorFrase`, `removeFrase`, `dragPhraseBoundary` (drag a locked phrase's edge — grow it, shrink the immediate neighbor only when they touch; ENG-342 replaced the old reopen/⚑), the navigation entries `enterScene`/`enterFrasesLayer`/`enterSegmentacao`, and `confirmFrasesDone` (empty-scene warning once PER SCENE; advances to the next productive scene or ENDS the session — `kind: 'finished'`, `mode: 'concluida'` via `setMode` from @/domain/gates.ts. Until ENG-691 this branch asked for `mapeamento`, the interview mode; the domain-level meaning — "no more scenes left to segment" — is unchanged, only the mode it now writes changed name).
- **`domain/mapeamento-scripts.ts` and `domain/mapping.ts` are gone (ENG-691, scope cut 2/4).** They held the verbatim Mapeamento question scripts (`L1_Q`/`L2_Q`/`L3_Q`, reference L1030–1056, including the ENG-604 byte-freeze exception recorded in @/CLAUDE.md) and the lazy answer store over them (`ensureMapping`/`setAnswer`/`productiveFrases`/`questionSequence`/`voiceAnswerPath`) respectively. Both left the layer whole: nothing in `domain/` references a `mapping` field or a question script any more, and the reference-parity byte-freeze test they carried left with them. `docs/reference/index.html` still carries the ENG-604 wording (CLAUDE.md's exception record), but nothing in this repo ports it any more.
- Each module carries colocated tests (`*.test.ts`). Hash tests pin known vectors computed by an independent Python oracle (the emulation script is quoted in @/domain/hash.test.ts) plus vectors that were originally derived from the (now-deleted) golden harness's committed expected outputs — hardcoded into the test with a comment recording their provenance, so the assertions survived the harness's removal in ENG-691 even though the directory they were checked against did not.
- Non-negotiable facts this layer implements exactly (details in @/docs/PRD-colar-de-sons-v2.md §10–§11 and @/CLAUDE.md):
  - Bead indices are the universal coordinate. `S#` sequential scene IDs, reassigned on export, were an export-time concern of the now-deleted @/contracts/retorno.ts (ENG-691) — `domain/` only ever allocates `PT#`/`P#` (@/domain/ids.ts), stable and lowest-free.
  - Frontier: sequential locking (@/domain/scenes.ts, @/domain/phrases.ts); post-lock adjustment is dragging the END of a scene/phrase (`dragSceneBoundary`/`dragPhraseBoundary`, ENG-342 — now IDENTICAL and **Pac-Man/tiled** for both, owner decision: the NEXT segment follows the boundary in both directions (its start becomes `newEnd+1`), so shrinking never opens a gap — the next grows to fill — and growing pushes the next; the last segment (no next) grows/shrinks freely to the story/scene end). Only the END drags — the start is the seam, moved only by dragging the previous segment's end. See @/docs/segmentation-rules.md for the full rule set. The drag reducers are pure span editors; the station composes `primePart`/`primeFrase` after each drag to re-anchor the pending slot on the new frontier (else a following click closes at the stale seam — with a phrase covering the necklace end, past the grid). First phrase may back-reach into the previous scene (@/domain/frontier.ts); seam-move threshold `max(3, 25% of scene)` and two-productive-scenes escalation (@/domain/seam.ts).
  - Gates: whole story → scenes → (all triaged + ≥1 productive) → segmentação → **end**. All-none-fit locks downstream. Confirming the last productive scene's phrasing moves the session to `mode: 'concluida'` — the end of the domain's own flow, with no `modeLocks` key of its own (ENG-691); the `(+ ≥1 phrase)` clause that used to gate a `mapeamento` station beyond segmentação is gone with that mode, since `concluida` has no lock to require. Since ENG-725 the UI (@/ui/pages/review, @/ui/app/stepper-model.ts) gives this same mode its own station — reachability there is the mode itself, not a `modeLocks` entry — but that is a `ui/` decision layered on top; nothing in this frozen layer changed to support it.
  - Confidence stored as `high`/`medium`/`low` (ENG-356 — o artefato é inglês, though there is no artefato left to be English since ENG-691 — see @/CLAUDE.md); tag states `pending`/`tagged`/`none_fit`.
  - **There are no Mapeamento scripts any more.** The 11 L1 / 5 L2-per-scene / 5 L3-per-phrase question set and its voice-answer keying (`respostas/level{1,2,3}/…/<k>.webm`) lived in `domain/mapeamento-scripts.ts`/`domain/mapping.ts`; both were removed in ENG-691 along with the interview.

### Things to Know

- **FROZEN LAYER / contract-critical:** any PR touching this folder requires human review; autonomous loop agents must stop and escalate rather than merge. Until ENG-691 a change also required the golden harness green; that harness is gone (see How it fits into the larger codebase), so explicit human approval is now the _only_ thing standing there.
- Coverage gate: ≥ 90% line+branch, enforced per-glob in @/vitest.config.ts. Every PRD §11 rule needs an explicit test, including edge thresholds (seam-move, partial bead, back-reach, boundary drag). Since ENG-691 this coverage is also the layer's only remaining proof against the reference. Snapshot tests do not count as coverage.
- `scene_kind` values are **English** and come from a generated list — never hand-edit; PT-BR labels are display-only and live in the UI.
- Complexity warnings are expected and accepted here: the port mirrors reference logic 1:1, so functions may exceed the lint's warn threshold (see @/eslint.config.js).
- When in doubt about behavior, read the reference's actual code — its behavior wins over any intuition or existing doc. Never "improve" reference behavior; fidelity is the requirement. Concretely: the `1e-9` epsilon and the `+(x).toFixed(6)` time coercion in @/domain/grid.ts, and the "quirks" of @/domain/hash.ts (only the 2 low bytes of sampleRate are mixed, only channel 0 is read, `Math.imul` because the naive `h * prime` product exceeds 2^53 and silently loses bits) are all byte-identity contract — do not fix them.
- Gate quirk mirrored ON PURPOSE (@/domain/gates.ts): `resolveMode`/`setMode` redirect on productive scenes ONLY, never phrases, so the guided flow can reach the end of the flow (`concluida`) with zero locked phrases. Until ENG-691 `modeLocks` also carried a STRICTER `mapeamento` tab lock (productive>0 && ≥1 locked phrase with span); that key is gone with the mode. All-none-fit locks downstream because zero productive keeps segmentacao/`concluida` redirecting back to triagem (`allNoneFit` in @/domain/coverage.ts names the same condition). `scene_kind`/confidence are stored only via @/domain/triagem.ts; PT-BR labels in @/domain/scene-kinds.ts (`SK_PT`) are display-only and never enter the stored data.
- Reference quirks in @/domain/scenes.ts are mirrored ON PURPOSE and are behavior contract, not bugs — e.g. every `confirmPart` leaves a fresh unlocked slot primed at the seam (it occupies a `PT#` and thus shapes ID allocation) while `confirmParts` discards leftover unlocked slots (their `PT#`s return to the pool); and entering the parts layer resumes on the LAST unlocked slot (an artifact of the reference's loop).
- Phrase-layer quirks in @/domain/phrases.ts, equally contract: `confirmFrase` does NOT check `pendingStart`, so a half-selection `{b,b}` confirms as a one-bead phrase; the phrase frontier with an active scene does NOT clamp at `totalBeads−1` — only the generic branch of `frontier` in @/domain/frontier.ts does — so with the last phrase covering the end of the necklace the frontier lands OUTSIDE the grid; dangling unlocked slots occupy their `P#` (auto-added by `enterScene`/`enterFrasesLayer`/lock); the cursor is asymmetric — locking and `enterScene` resume on the FIRST unlocked slot, `removeFrase` and `enterFrasesLayer` on the LAST; and when a selection crosses BOTH borders, the END side decides neighbor and delta in @/domain/seam.ts.
- The border-crossing decision is effects-as-data: `classifyBorderMove` (@/domain/seam.ts) returns a `BorderOffer` value and mutates nothing; the UI interprets it into `moveBorder`/`reanchorFrase`/back-to-triagem. The `max(3, round(0.25·span))` threshold is exact in IEEE-754 (0.25 is a power of two; ties round toward +∞ by spec), so it is deterministic across engines.
- `warnedEmptyScene` (the once-per-scene empty warning of `confirmFrasesDone`) is a module variable in the reference; here it is an explicit parameter/return — ephemeral UI state that deliberately does NOT enter `SessionState`. Each caller carries it between calls as local UI state (the Segmentação station).
- `enterSegmentacao` is only the scene-focus entry block that the reference runs inside `setMode('segmentacao')`; compose it AFTER `setMode` from @/domain/gates.ts. Inside the layer the dependency is one-way, `phrases → frontier → seam → triagem → state` (plus gates/ids/scene-kinds as leaves): @/domain/phrases.ts imports @/domain/frontier.ts and @/domain/seam.ts, never the reverse. This is why `activeScene` lives in @/domain/seam.ts — keeping it in @/domain/phrases.ts would create the cycle `frontier → phrases → frontier` (the depcruise no-cycles rule is an error).
- Deliberate, documented deviations from the reference exist only where the reference would fail silently or crash on inputs it never produces — byte-identity is unaffected. Examples: `buildBeads` validates `beadSec` itself (the reference validated in its UI caller), `spanDur` throws a typed error instead of a `TypeError` on `undefined`, and `whole.span` is typed non-null because `createSession` — the only constructor — always sets it. Conversely, `beadAtTime` intentionally carries NO guard: it mirrors the reference exactly.
- Validation in the reducers never throws: callers branch on discriminated results (`SceneResult`, `ConfirmFraseResult`, `FrasesDoneResult`), and the exact PT-BR strings live as contract-level copy in `SCENE_ERROR_COPY` (@/domain/scenes.ts), `FRASE_ERROR_COPY`/`FRASES_EMPTY_WARNING` (@/domain/phrases.ts) and `BORDER_COPY` (@/domain/seam.ts) — the UI must reuse them, never rephrase. Silent no-ops are also part of the port — e.g. `confirmPart` on a locked/absent slot returns `ok` without changing state, and `clickBead` ignores clicks while `review` is on.
- @/domain/hash.test.ts duplicates a seeded BigInt LCG PCM generator on purpose: domain code **and its tests** may not import from `tests/` or `adapters/` (dependency-cruiser rule), so it cannot reuse the canonical generator, which lives at @/adapters/audio/pcm.ts since ENG-691 moved it there from the now-deleted `tests/golden/pcm.ts`.
- No network calls, no `Date.now`-style ambient IO, no framework types. If a module seems to need one, the design is wrong — push it out to @/adapters behind a port.

# Noridoc: contracts

Path: @/contracts

### Overview

- Zod-4-validated DTOs and mappers — session state (the autosave document), pipeline delivery/return imports, and API/bucket payloads. **The artifact-building half of this layer is gone (ENG-691, scope cut 2/4):** @/contracts/manifesto.ts, @/contracts/retorno.ts, @/contracts/relatorio.ts and @/contracts/serialize.ts — the schema+mapper+export-gate trio for `bead-manifest.json`/`anchoring-return.json` plus the `<slug>-mapping-report.md` builder and the one JSON serializer — were deleted along with their fixtures and tests when the SPA stopped producing any artifact. See Things to Know for what that costs.
- What remains: @/contracts/session-state.ts (versioned full-session autosave DTO + round-trip mappers, ENG-234), @/contracts/imports.ts (the two pipeline import mappers, unaffected by this cut — they read a delivery/return INTO the session, which is a different direction from the deleted export builders), and @/contracts/api.ts/@/contracts/bucket.ts (endpoint + bucket DTOs, reconciled with the real tripod-api OpenAPI).
- Exists as its own frozen layer because the shape of what the SPA persists and exchanges with the API is the contract other systems depend on. Until ENG-691 this also carried the artifact byte-identity promise to the downstream pipeline; that promise, and the artifacts it covered, are gone.

### How it fits into the larger codebase

- Imports **only** @/domain (plus `zod`); enforced by @/.dependency-cruiser.cjs. Consumed by @/adapters and the `ui/` wiring layer.
- **The golden harness is gone (ENG-691).** Until then it byte-diffed this layer's artifact output against goldens generated from the reference @/docs/reference/index.html on every PR — the reason the layer was frozen. It was removed outright, together with the three artifacts it diffed, when the owner decided the app would stop producing them. The layer stays frozen (contract-critical, human review required), but that review is now the only thing standing there; see @/CLAUDE.md's "The golden harness is gone" section.
- @/contracts/session-state.ts's mappers take the domain's `SessionState` (@/domain/state.ts) as their round-trip input; @/contracts/imports.ts's mappers take a pipeline DTO and PRODUCE a `SessionState`. Neither direction routes through i18n or emits translated copy — the frozen-layer rule (@/ui/i18n/docs.md).
- **There is no downstream custody rule left to enforce here.** Until ENG-691, every system that stored or transported the three artifacts treated them as opaque bytes (PRD §10.5), and `SessionStore.complete()`/`getArtifacts()` in @/adapters/sessions were the custody boundary. That machinery is untouched in @/adapters (frozen-adjacent, out of this slice's scope) but nothing in `ui/` calls it any more (@/adapters/sessions/docs.md) — there are no bytes for it to receive. The wire types it still exposes (`ArtifactResponse`, `ArtifactUploadResponse` in @/contracts/api.ts) describe the tripod-api's own artifact-upload endpoint, which this repo simply does not reach today.

### Core Implementation

- **The artifact export trio is gone.** `serializeArtifact` (raw-UTF-8 `JSON.stringify(value, null, 2)`, no BOM, no trailing newline), `buildManifesto`/`ManifestoSchema`, `buildRetorno`/`RetornoSchema`, and `buildMapReport`/`relatorioFilename` — all removed in ENG-691 along with their fixtures under `fixtures/manifesto`/`fixtures/retorno` and the report's PT→EN divergence table that the (also-removed) golden harness enforced. Nothing in this layer serializes JSON or Markdown for export any more.
- **Session state** (@/contracts/session-state.ts): the autosave DTO (PRD §7.3) that lets a session resume from any machine — no reference 1:1, since the v1 prototype never persisted. `SessionStateDtoSchema` is a `z.strictObject` (bad enum/type/`schema_version`/extra key all reject) that serializes **every** domain `SessionState` field (@/domain/state.ts) including the full grid `beads[]`, plus a separate `SessionMeta` for the fields that don't live in the domain: `granularityLevel` (§8.1, reusing `GranularityLevelSchema` from @/contracts/bucket.ts), `bucketAudioId` (§7.4) and `pipelineConsent` (§12/O6). `toSessionDto(state, meta)`/`fromSessionDto(dto)` are the round-trip pair — `toSessionDto` now takes exactly these two arguments.
- **`schema_version` is a single literal, 4, with NO migration path (ENG-691).** Earlier versions existed for real reasons — v1 (ENG-357) was the PT-BR shape (`statement_pt`, confiança `alta`/`média`/`baixa`); v2 (ENG-356) the English shape; v3 (ENG-514) added `reviewComplete` — and `fromSessionDto` used to accept all three and upgrade them. v4 is the shape with **no interview**: `mapping`, `voice`, `voiceVersion` and `reviewComplete` are gone from the DTO, and the `mapeamento` mode value is gone from the `mode` enum. The upgrade chain (`upgradeV1`/`upgradeV2`, the v1/v2 sub-schemas) was deleted along with those fields, and this is a deliberate owner decision (2026-09-01), not an oversight: a pre-cut document carries interview answers this product has nowhere to store, so a tolerant schema would half-load it and lose that data silently on the next autosave. `fromSessionDto` now rejects anything but the current shape outright — a session saved before the cut fails loudly on read, leaving the document intact on the server for another tool to read. `SessionMeta`/`toSessionDto` lost their `voice`/`voiceVersion` fields for the same reason.
- **Pipeline imports** (@/contracts/imports.ts, unaffected by ENG-691): 1:1 ports of the reference's two interop handlers (@/docs/reference/index.html). `applyDelivery(session, dto)` maps a delivery into **UNLOCKED** proposals — spans from `proposed_span` else null, tag/kind prefills preserved, `PT#`/`P#` index fallbacks, `whole.id` overwritten only when `scene_id` is present, and a **non-blocking** `manifestMismatch` flag (true only when `manifest_id` exists and differs from the session's). `applyReturn(session, dto)` maps a return into **everything LOCKED** — spans from `confirmed_span` (schema-required), `partsConfirmed` set when parts exist and never unset, NEEDS_REVIEW flags reapplied by `prop_id`, cursor moved to `frases`, and **no** manifest check (mirrors the reference). Both return a discriminated `ImportOutcome` and reject with `{ok:false, reason:'no-grid'}` when the grid is absent (`totalBeads` 0). PT-BR copy is exposed as `DELIVERY_NO_GRID_MSG`/`RETURN_NO_GRID_MSG`/`MANIFEST_MISMATCH_MSG` constants for the imports UI (ENG-248) to reuse. The `ReturnSchema`/`DeliverySchema` here describe a pipeline document coming IN — a different shape from (and, since ENG-691, the only surviving cousin of) the deleted `RetornoSchema` export builder; a colocated test that used to prove `retorno → import → export` byte identity was removed with the export half, since there is no export to round-trip against any more.
- **API / bucket** (@/contracts/api.ts, @/contracts/bucket.ts, untouched by ENG-691): the endpoint DTOs the SPA consumes, **reconciled with the real tripod-api OpenAPI** during ENG-247 (a filtered production snapshot lives at @/contracts/openapi.json with generated types in @/contracts/generated/tripod.d.ts, refreshed by @/scripts/api-snapshot.mjs). Auth mirrors the house wire: email login returning the `AuthResponse` envelope (user + rotating token pair), app roles via `my-roles`. Sessions/artifacts/resources mirror the wire verified in ENG-267: `CompleteSessionRequest` and `ResourceRef` were **removed** (they never existed on the wire — `POST /complete` has no body; artifacts travel as raw multipart bytes), replaced by `ArtifactResponse`/`ArtifactUploadResponse` (the multipart upload receipt with per-artifact checksums) and `ResourceSummary`/`ResourceListResponse`/`ResourceUrlResponse` (voice-answer listing + the short-lived signed GET URL for the second, Bearer-less hop) — this half of the module describes the server's own lifecycle and is unreachable from `ui/` today (see How it fits into the larger codebase). `RenameSessionRequestSchema` (ENG-281, backend `shemaobt/shema-api#153`/ENG-414, open but not yet merged) is a `z.strictObject` carrying a single `story_name` key whose `trim`/`min(1)`/`max(255)` mirror the server's `StringConstraints` (`strip_whitespace`, so a name of nothing but spaces is refused rather than stored) — `story_slug` NEVER travels here, since the server still files stored resources under it, and the `strictObject` is what makes that absence a rule an extra key would fail, not a habit. Remove has no request DTO (the `DELETE` carries no body) and reuses `SessionSummarySchema` for the rename response — no cloned schema. Two custody invariants matter: (1) **artifact payloads are opaque** — `OpaqueArtifactSchema` is `z.string()` and this module contains no `JSON.parse`/`JSON.stringify` call (asserted by a source-grep test); (2) the **acousteme envelope** carries the tokenizer grid that resolves granularity — `codebook_version` (a string, confirmed by the real OpenAPI), `hop_sec` + `granularity_frames {small, medium, large}` (§6.1/§15.2 O8), from which the `GranularityResolver` (@/adapters/granularity) derives `beadSec = frames[level] × hop_sec`. `SessionStatusSchema` carries the §7.3 lifecycle in ascii (`in_progress` → `completed`; accented labels are display-only, resolved in @/ui/i18n). The autosave body is typed as a `z.looseObject({schema_version})` here because the real full-state schema is @/contracts/session-state.ts; adapters import only the interface types so the swap stays contained. `fixtures/api/bucket-list.json` is the adapter-facing bucket listing (three audios: with/without acousteme, consent varied) — PRD-derived, documented in `fixtures/api/README.md`.
- Zod 4 idioms are mandatory: import from the root `"zod"` only (`zod/v3`/`zod/v4` subpaths are lint-banned in @/eslint.config.js because they mix eras silently); `z.strictObject`, `.extend()` not `.merge()`, two-arg `z.record()`.

### Things to Know

- **FROZEN LAYER / contract-critical:** changes require explicit human approval in the PR. Until ENG-691 they also required the golden harness green; that proof no longer exists, so human review is now the _only_ thing standing there — weigh a change to this layer accordingly.
- Coverage gate ≥ 90% (glob thresholds in @/vitest.config.ts), and every schema must have both a **valid and an invalid fixture** test.
- The depcruise rule `contracts-so-domain` has **no test exemption**: `contracts/*.test.ts` cannot import from `tests/` — fixtures are read with `node:fs` instead (Node builtins are allowed in tests).
- `scene_kind` stays `string | null` at the type level (the enum is runtime-derived, so Zod's inference widens to `string`) — the 27 kinds are enforced ONLY at validation time, by `SessionStateDtoSchema` (@/contracts/session-state.ts) and the import schemas (@/contracts/imports.ts). Always serialize the ORIGINAL mapper literal, never a parsed result, if a future caller re-adds a JSON export here — Zod reconstructs objects in schema-shape order, which would break byte identity.
- **Strict vs. lenient is intentional:** the import DTO schemas (@/contracts/imports.ts) use lenient `z.object` (ignore unknown keys, faithful to the reference which reads only specific fields), UNLIKE @/contracts/session-state.ts, which uses `z.strictObject`. So an import-fixture invalidity is **semantic** (bad confidence enum, non-int bead, missing `confirmed_span`), never "extra key".
- The API/bucket schemas are no longer provisional: they mirror the published tripod-api OpenAPI (snapshot + generated types under @/contracts/generated, closing O9 from PRD §15.2). Lessons baked in: never model a request the wire doesn't have (the removed `CompleteSessionRequest`), and never be stricter than the wire on a response (`duration_sec` is nullable because the API validates on ingestion, not on listing). Any further drift still goes through the frozen-layer process.
- **Byte-identity used to be fragile by nature** — key order, number formatting, newline discipline — and that is why `serializeArtifact` was the ONE serialization path in the app. There is no other JSON serialization path to introduce now that it is gone; if this layer ever regains one, that invariant is the one to re-establish first.

## DTO versioning (ENG-357/ENG-359/ENG-514/ENG-691)

- **No artifact filenames survive to document.** `<slug>-bead-manifest.json`, `<slug>-anchoring-return.json`, `<slug>-mapping-report.md` and their `story`-fallback rule lived in the deleted @/contracts/serialize.ts/@/contracts/relatorio.ts; there is nothing left in this layer that names a downloadable file.
- **`schema_version` is the single literal `4`, and `fromSessionDto` accepts nothing else.** The version history: 1 (ENG-357, PT-BR shape) → 2 (ENG-356, English shape) → 3 (ENG-514, added `reviewComplete`) → 4 (ENG-691, removed `mapping`/`voice`/`voiceVersion`/`reviewComplete` and the `mapeamento` mode value when the interview left the product). Versions 1–3 used to be accepted and upgraded on read (`upgradeV1`→`upgradeV2`, then promoted to the current shape on the next write); that upgrade chain is gone. `fromSessionDto` receives `unknown` and is the **single validation point at the read boundary** (the adapter delivers the raw body — `http.ts`: "validated in depth by the state layer, not here"); anything that isn't schema-version-4-shaped — an old version, an extra key, a wrong type — throws.
- **This is a deliberate owner decision (2026-09-01), not a gap.** A session saved before the cut carries interview answers this product has nowhere to store any more; tolerating it on read would silently drop that data on the session's next autosave. Failing loudly instead leaves the old document untouched on the server, readable by another tool later. `SessionStateDtoSchema` is `z.strictObject` by custody, so this was already true of any mismatched shape before ENG-691 — the version bump only changes the error from "unknown key" to "wrong version", it does not change the refuse-by-default posture. Anyone with a v1–v3 session open across this deploy needs to reload; there is no silent carry-forward.

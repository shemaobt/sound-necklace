# Noridoc: ui/i18n

Path: @/ui/i18n

### Overview

- The language layer of the app (ENG-279): PT-BR (default) + EN for the **UI chrome only**. It owns the i18next init, the two dictionaries, the display translator for copy that originates in @/domain (scene-kind labels), and the Vitest setup file that initializes i18n for every UI test. Since ENG-689 (scope cut 1/4) that is the only translator left: `questionTextFor`/`questionNoteFor`/`questionExampleFor` and the scripted-interview translators (`ui/i18n/conversation-questions.ts`, `ui/i18n/interview-language.ts`) were deleted along with the Conversation station that consumed them.
- It exists because facilitators may be English-speaking while the listener and the story are not. It used to carry a second, load-bearing job — keeping the UI language away from the frozen PT-BR the downstream pipeline ("o Compilador") consumed, on the rule that _what a person reads on screen is translatable; what is written to an artifact is not_. **There is no artifact and no downstream any more (ENG-689/ENG-691)**, so that half of the rationale is spent; the layer is now display translation and nothing else. The one value it must still never translate at the storage level is the scene-kind `value`.
- The chosen language persists in `localStorage` (a namespaced, versioned key) and is re-read at init, so it survives a reload. The header toggle (@/ui/app/header.tsx) is the only writer.

### How it fits into the larger codebase

- Sits at the same depth as @/ui/organisms in the atomic ladder (see @/ui/docs.md): it may import @/domain (types + pure display helpers) and npm, never adapters — so the @/.dependency-cruiser.cjs rule "only pages/templates/app import adapters" holds without an exception. It imports nothing from @/contracts.
- Consumed by @/ui/organisms, @/ui/pages and @/ui/app/header.tsx. **@/ui/atoms and @/ui/molecules never import it**: they stay purely presentational and receive copy through props. Their PT-BR prop defaults (e.g. the DocumentCard download label, the ConfidenceTrio disc labels) are the one place untranslated chrome copy still lives — a caller must pass a translated label to override them.
- **There is no artifact path left to touch (ENG-691).** Until then, `domain` (PT-BR scripts, scene_kind values) fed `contracts/` builders that produced `anchoring-return.json`/`bead-manifest.json`/`mapping-report.md` — byte-frozen, PT-BR, diffed by the golden harness — while `ui/i18n` fed only `ui/organisms`/`ui/pages` for DISPLAY. @/contracts/relatorio.ts used to serialize the question text verbatim from @/domain/mapeamento-scripts.ts, and the invariant this section used to describe — "no translated string is ever written into `SessionState`", proven by an EN byte-identity e2e spec that drove the real UI, switched it to EN, and diffed the three exported artifacts against @/tests/golden — no longer applies to anything: the builders, the scripts, the golden harness and that spec are all gone (see @/CLAUDE.md's "The golden harness is gone" section). What survives is the STRUCTURAL half: the `contracts-so-domain` rule in @/.dependency-cruiser.cjs still makes it a CI failure for @/contracts to import anything from `ui/`, so a translated string still cannot reach @/contracts/session-state.ts's mapper by construction — there is just no artifact on the other end of it any more. The scene-kind `value` (`GLEANING_SCENE`) remains the one contract value this layer must never translate at the storage level, since it is what a future re-integration with o Compilador would key off.

- **Neither @/domain nor @/contracts was modified** to add i18n, and neither should be: they are frozen layers. This is why user-facing copy that is DEFINED there still renders PT-BR under an EN UI — the domain gate/error copy (`triageDone`'s message, `SCENE_ERROR_COPY`, `FRASE_ERROR_COPY`, `BORDER_COPY`) and the import precondition messages in @/contracts/imports.ts. Translating those means changing a frozen layer, which is contract-critical and deliberately out of scope for a `ui/`-only change.
- **The station labels have exactly one source** (`stations.*`). The shell's progress band (@/ui/app/stepper-model.ts holds `labelKey`, @/ui/app/story-progress.tsx translates — the band inherited this when ENG-668 retired the fio-de-contas dots) and the Dashboard's progress glance both read it. They used to hold separate copies, which is how an EN dashboard could sit next to a PT shell — if you add another station, add the key once.
- **Copy that lives in a molecule as a prop default is a leak waiting to happen.** Molecules are presentational: the organism/page passes translated copy in (`downloadLabel`/`downloadedLabel`, `roleTitle`, `dotLabel`, `stateLabels`). The PT-BR defaults exist only so a molecule renders standalone in its own test — a caller that forgets to pass the prop ships PT-BR into the EN UI, and nothing fails. The `atomos-e-moleculas-sem-i18n` rule in @/.dependency-cruiser.cjs stops the tempting fix (importing `t()` into the molecule), because @/ui/i18n imports @/domain and a molecule must not reach it, not even transitively.

### Core Implementation

- **Init is synchronous, inline and provider-less** (@/ui/i18n/index.ts). Resources are bundled objects (no HTTP backend, no lazy namespace load) and `initReactI18next` registers the singleton globally, so no `<I18nextProvider>` is mounted anywhere — `useTranslation()` just works in any component. @/ui/app/main.tsx imports the module for its side effect **before the first render**.
- **No `i18next-browser-languagedetector`.** It was rejected: its cache/detect ordering overwrites the saved choice on reload. Persistence is done by hand instead — `initialLang()` reads the storage key (unknown or missing value falls back to PT), and `setLang()` changes the language, writes the key, and sets `<html lang>`. Every storage access is wrapped in try/catch and degrades to a session-only choice, the precedent set by the tutorial popup (@/ui/organisms/tutorial-popup/README.md).
- **PT/EN key parity is enforced by the typechecker, not by tooling.** `pt.ts` exports the dictionary WITHOUT `as const` (values stay `string`) plus `export type Dict = typeof pt`; `en.ts` declares its dictionary as `const en: Dict`. A missing key fails the build, an extra key trips the excess-property check. Adding a string = adding it to both files.
- **`sceneKindLabel(value, lang)`** (@/ui/i18n/scene-kind-label.ts) is the display label of a `scene_kind`: PT uses `skShort` (PT-BR label, English fallback), EN uses `skEnShort` — the same short English @/domain/scene-kinds.ts defines (the report `.md` that used to emit it too was removed in ENG-691, see @/contracts/docs.md; `skEnShort` itself is untouched). It replaced direct `skShort` calls in the Triage picker, the coverage drawer, and the Triage/Segmentação stations. The stored value never changes.
- **It is a pure function taking `lang` explicitly**, not a hook — callers thread `i18n.language` from `useTranslation()`. That keeps it unit-testable with no i18n init and keeps the hook count in the organisms down.
- **`test-setup.ts` is a Vitest `setupFiles` entry** for the `dom` and `browser` projects (@/vitest.config.ts). Importing it initializes i18n in PT for every UI test and its `afterEach` resets the language, so a test that switches to EN cannot leak into the next one.

### Things to Know

- **The invariant this folder guards is narrower than "PT/EN parity everywhere":** no **dictionary** string may ever reach `SessionState` — `t()` in a domain write is the bug, regardless of which page does it. (The confirmation flow that used to write a human-confirmed English answer into `SessionState` — ENG-326/ENG-327, @/adapters/stt feeding @/ui/pages/report — left with the interview in ENG-689; the rule survives it because it never depended on that one flow.)
- **A surface rendered without the init shows raw keys** (`login.title` instead of "Entrar"). That is the failure mode to recognize: production is covered by the side-effect import in @/ui/app/main.tsx, tests by the setup file. A new Vitest project that renders UI must add the setup file too.
- **Action labels and headings start with a capital, in both dictionaries** (ENG-510). Sentence case, never Title Case, and only the first letter — the wording, punctuation and meaning are untouched. It covers what NAMES a control (a button or field, whether the name is visible text, an `aria-label` or a `title`) and what titles a section; when one UI slot cycles through several keys (the mic's record/saving/stop, a play/pause/opening button), they all follow the slot so the case never flickers. It deliberately does NOT cover values, statuses, placeholders, the short description under its own label, a fragment that renders inside a sentence, the accessible name of a region or image, or copy the CSS already upper-cases (the eyebrows) or lower-cases (the draft badge) — there the written case is invisible. One shape stayed lower-case on purpose even though it reads like an action: the `downloadedLabel` prop default in @/ui/molecules/document-card, which is molecule copy rather than dictionary copy — no page passes a dictionary value to it any more (the molecule has had no caller since ENG-689 removed Export).
- **Existing PT-BR copy is a contract with the test suite.** The unit suites and the Playwright specs (@/tests/e2e — see its `ColarApp` page object) select by verbatim PT-BR strings, which now live in `pt.ts`. Editing a PT value there breaks those selectors at a single point, by design.
- **Translated labels can no longer be identifiers.** Two call sites had to gain stable ids when their copy became translatable: the Triage picker's theme blocks carry a slug `data-theme` (`indo-e-vindo`) instead of the visible name, and the seam modal's action list carries a `key` because the label no longer identifies the focus-target button. Any new code that keys off visible copy has the same bug in waiting.
- **The Triage filter matches three things** — the PT-BR label, the currently displayed label, and the English contract value — so filtering never gets worse by switching language.
- Interpolation runs with `escapeValue: false` because React already escapes; passing raw HTML through `t()` would be an XSS foot-gun that nothing here does.

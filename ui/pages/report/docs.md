# Noridoc: report

Path: @/ui/pages/report

### Overview

- The report station (ENG-250): the consolidated, **editable** mapping report (PRD v2 §8.7 "The report", redesign §6.6). One card per question, in the exact order the domain produces (`questionSequence`), each numbered `Q<n>` by its position in the conversation. **Downloading is the NEXT screen's job** — the footer's single action is "Guardar os documentos →".
- A wiring component: it reads the pure @/domain session through the @/ui/state session store, renders an editable card per question, dispatches text writes through the domain answer store, plays voice answers through the injected `VoiceRecorder` port, and — since ENG-327 — hosts the **review of machine drafts** (transcription + PT→EN translation) coming from the `Transcriber` port (@/adapters/stt).
- **This is where a recorded answer becomes text.** The recording never reaches the artifact. Since ENG-370 the human confirms the TRANSCRIPT, in the language it was spoken, and that is what the review shows; the English rides along under `EN_ANSWER_PREFIX` and is what @/contracts serializes. That makes this station a required stop, not a nicety: @/contracts `reportExportStatus` blocks the export while any recorded answer still has no confirmed text.
- **And since 2026-08-12 it can confirm all of them at once.** A real session arrived with 467 recorded answers and no confirmed text; the gate refused, correctly, and 467 individual clicks is not a workflow. The owner chose bulk confirmation over an override, so the gate is untouched — this **satisfies** it and nothing bypasses it. The policy consequence (a human attesting to N drafts in one act instead of N readings) is recorded in PRD §12 and in the repo's CLAUDE.md carve-out list.
- Facilitator surface (§7.2): unlike the listener screens, digits/IDs are allowed here — the report lists scenes and phrases with numbers, kinds and section headers.

### How it fits into the larger codebase

- **The station after the conversation.** It self-registers through the `import.meta.glob('/ui/pages/*/index.tsx')` registry, and is ALSO resolved directly by @/ui/pages/conversation (a static `import.meta.glob('/ui/pages/report/index.tsx')`) so the "próxima" at the last conversation question opens the report. Both consume the default export.
- **Question order is the domain's.** The flat card order comes verbatim from `questionSequence` (@/domain/mapping.ts): L1 `L1_Q` → per `lockedParts` (none_fit included) `L2_Q` → per `productiveFrases` `L3_Q`. The UI only inserts section (level) and scene/phrase group headers as it walks the sequence; those headers and the card's question text follow the UI language (`questionTextFor`, @/ui/i18n/conversation-questions.ts), while the question's `field` hint still renders the raw domain value.
- **The screen translates, the `.md` does not** (ENG-279). The card text comes from `questionTextFor`, but `buildMapReport` (called only by @/ui/pages/export) reads the PT-BR scripts straight from @/domain — @/contracts cannot import `ui/` at all (a dependency-cruiser rule) — so the exported **questions** are byte-identical regardless of the UI language, and the golden harness keeps that output pinned. The **answers** are a separate matter: the confirmed text is English by product decision (ENG-326), and it is written into `SessionState` by a human action here, never by `t()`.
- **The transcription job is no longer asked for ONLY from here.** @/ui/pages/conversation now fires it as the facilitator advances past each recorded answer — moving on is the acceptance signal — so by the time the report opens most drafts are already `ready`. This station keeps its own trigger and becomes the **safety net**: the hook @/ui/pages/report/use-stt-drafts.ts starts the job on open and polls until it finishes, and because the endpoint is idempotent it simply seeds whatever a lost request left behind. The station consumes drafts and never lets one become an answer on its own.
- **The force is scoped, and both sides of its comparison are durable.** A re-transcription is asked for only when a stored draft belongs to a take that no longer exists, which the page decides by comparing each answer's `enver__` (seeded into the answer store when the draft was made) against `recordingVersion`. Both have to survive a reload and for a long time only the first did: `recordingVersion` was React state that reset to `{}` on every load, so reopening a session compared a stored `"1"` against a fresh `"0"`, read every answer as re-recorded, and sent a session-wide force — an interview spread over two sittings paid the provider for all of its answers again, once per reopen, and reset drafts a human had already reviewed. It now comes from `SessionMeta.voiceVersion` (@/contracts/session-state.ts), persisted through the same autosave as `meta.voice`. Two absences read as "nothing to redo": no `enver__` means never transcribed (the ordinary POST seeds it, and forcing would reset every OTHER answer to do it), and no entry in `voiceVersion` means a session older than the field, where the stored draft is the only truth available. The force that does go out names the changed answers (`paths`), so redoing one take costs one transcription instead of the whole interview. An explicit retry stays session-wide — the button raises `attempt` from a failed card but says nothing about which.
- **Answers.** Text edits write through `setAnswer` (@/domain/mapping.ts) — the lazy answer store created/extended by `ensureMapping`; the store never loses answers. Voice answers are detected through the injected `VoiceRecorder.has(path)` (@/adapters/voice), keyed by the canonical `respostas/level{1,2,3}/…/<k>.webm` path from `voiceAnswerPath` (§10.4/O5); the play affordance calls `recorder.play(path)`.
- Reads session via `useSessionStore`, writes only through `sessionStore.apply` (see @/ui/state/docs.md), so the store's editability gates (online/review/lock) can silently pause a write. Per @/.dependency-cruiser.cjs, @/ui/pages may import @/domain, @/contracts, @/ui/state, @/ui/atoms and adapters.

### Core Implementation

- **Header + white cards** (realigned to the Protótipo): a new `<header>` (eyebrow + serif italic headline, `report.eyebrow`/`report.headline`) sits above the question list; each `ReportCard` is now a white card (`--cds-radius-card-sm`, `--cds-shadow-card`) instead of the previous cream-tinted bordered card. Purely visual — the card content/order is unchanged.
- **`Report({ recorder, preloaded, stt, sessionId })`** (@/ui/pages/report/index.tsx): subscribes `session`; renders `null` until a session with a non-empty question sequence exists. A `useMemo` derives `mapped` = `session` if it already has a mapping, else `ensureMapping(session)`, so answers render before the mount effect persists the store (which calls `sessionStore.apply(ensureMapping)` once when `session.mapping` is null). `stt`/`sessionId` are optional — without either, the station degrades to typing only.
- **Voice discovery, per answer and without a barrier** (ENG-319/ENG-337). One effect probes `recorder.has(path)` per question path and, when there is a recording, reads `recorder.duration(path)` after; it keeps a set of voiced paths, a set of already-CHECKED paths, and a `path → seconds` map. A path the caller already resolved (`preloaded`) is never re-asked. Until a path is checked the card shows a dimmed "procurando" row rather than the empty state — loading is not the same as no answer. The voiced set drives the voice row, decides which paths go to the transcription job, and counts the answers still awaiting confirmation; it never reaches the `.md` builder, which no longer takes a voice argument at all.
- **Draft lifecycle** (ENG-327): the voiced paths go to `useSttDrafts`; a returned `en` is seeded ONCE into the reserved `en__<k>` key, edited freely in place, and confirmed by writing it into the real answer slot through the same `setAnswer` path a typed answer uses. Seeding is guarded twice — a per-path `seeded` ref, and a check that the reserved key does not already EXIST in the bucket — so a re-mount (returning to the session, a reload) cannot resurrect text a human already deleted. `readAnswer` returns `''` for both "never written" and "emptied", which is why existence, not emptiness, is the test.
- **The freshness key is the draft's `generation`, not the recording's version.** A real session was transcribed before the disfluency cleanup existed, re-transcribed on the server successfully, and still exported the stutters. The seeding guard compared `enver__<k>` against `recordingVersion` — and a server-side re-transcription never touches the recording, so that comparison read "unchanged" forever; on a session predating `voiceVersion` both sides were `0` and it could never read anything else. The stored draft was then confirmed into the cell, `en__` kept its old English, and `answerCell` prefers `en__`, so the artifact carried raw ASR. Seeding now keys on **both**: the stored draft survives only when the recording version AND the `gen__<k>` generation still match what the server is offering; either moving supersedes it. The two absences read **differently on purpose** — no `enver__` means never transcribed (forcing there would reset every other answer's draft), while no `gen__` means seeded before we recorded which generation it was, which is precisely the session that has to give way. What never moves is the other guard: a **filled cell is skipped whatever the generation**, so nothing seeding does can overwrite an answer a human already put there.
- **An English interview has no translation to preserve, so confirming discards `en__`.** The job's translator returns its input untouched when the spoken language is already English (`platform/translation.py` in `tripod-api`), which means `en__<k>` holds the recogniser's **verbatim** — hesitations, restarts, repeated words. Since @/contracts `answerCell` prefers `en__` over the cell, the correction a facilitator had just made to the transcript was dropped from the `.md` in silence and the artifact carried raw ASR. `confirmDraft` now clears `en__` on that path, so the confirmed cell is what the artifact emits; under PT it keeps `en__`, because clearing it would export Portuguese. Which path applies comes from `interviewIsEnglish` (@/ui/i18n/interview-language.ts) — the SAME rule @/ui/app/App.tsx uses to tell the job the interview locale, kept in one place so the two cannot disagree about which path the answer took.
- **Confirming goes through the server, and that is what makes an edit reach the artifact.** For a long time `confirmDraft` wrote locally and told nobody, so under PT a corrected transcript never changed `en__` — and since `answerCell` prefers `en__`, the `.md` carried the translation of the sentence the correction had replaced. This was recorded here as unfixable for want of an endpoint; that note was stale, and the endpoint (`PUT …/transcriptions/{path}`, `Transcriber.confirm`) is now the confirmation path. It sends **only the spoken-language text** plus the generation the draft carried — the English is never the client's to state — and the `translation_en` that comes back becomes `en__`. Re-confirming text the server already holds costs nothing there (identical text returns before any translation), which is why every confirm can take this route.
  - **A refused confirm does not confirm.** Writing the cell anyway would leave it beside an English describing a different sentence, and the document would ship it — the same bug, now with nothing on screen to reveal it. So the cell stays empty, the export gate stays red (which is the truth), the corrected text stays in the field, and the card says so through a `role="alert"` line. A **conflict** is handled differently from a plain failure because it demands the opposite reaction: retrying replays the same superseded generation forever, so it triggers `refresh()` on the hook — a re-read that forces no reprocessing and, deliberately, does not change the `jobKey`, so the screen does not fall back to the wait over one answer.
  - Without a port, a session id, or a known generation there is nobody to ask, and the local confirm remains — §8.7 admits no dead end.
- Nothing anywhere removes speech disfluency in the SPA — the cleanup is the server's, and the translation prompt is explicitly instructed not to do it.
- **`ReportCard`** renders one question. A typed answer shows an editable `textarea`; a voice-only answer (recording present, no typed text) shows the voice row (▶ play + decorative waveform + duration slot); an empty answer shows the `textarea` with the "ainda sem resposta gravada" placeholder — or "sem resposta" when the interview marked the question as declined (`isSkipped`, @/ui/pages/conversation/answered.ts), since "ainda" promises an answer that is not coming. `ausencia` questions carry the wordless role marker.
- **The card is quiet by design** (prototype parity). The typed answer is a borderless, one-line field that grows with its text (`field-sizing: content` over `rows={1}`): empty, its italic placeholder reads as the prototype's "ainda sem resposta gravada" line, so a facilitator who will not write sees prose, not a form — 41 fixed 64px boxes read as a questionnaire. The note invite is a `+` text link, not a pill.
- **Reserved answer keys are the persistence trick, used twice.** The facilitator note (`nota__<k>`) and the English draft under review (`en__<k>`) are both stored via `setAnswer` in the SAME bucket as the answer they belong to. Because the mapping buckets are free `record<string,string>`, they round-trip through the autosave DTO (@/contracts/session-state.ts) for free — but `buildMapReport` only ever emits the question keys (`L1_Q`/`L2_Q`/`L3_Q`), so neither can appear in the exported `.md` (§10.4: the frozen skeleton has no note or draft lines). "An unconfirmed draft never enters an artifact" therefore holds **by construction**, not by the builder's author remembering to exclude it.
- **While the job runs, the wait IS the screen** (ENG-367), not a word inside each of the 41 cards: the header and every card are replaced by the `PreparingSession` comet, so nobody edits text that is still about to change. Two things follow from the sheet being emptied rather than unmounted. The `.cds-report` section drops its own document surface through `.cds-report--waiting` (`background: none; padding: 0`) — the 760px column with its background still painted over an empty body rendered as a band across the screen. And it reports the state upward through `onWaitingChange`, in a **layout** effect so the parent reacts before paint: the navigation footer lives in @/ui/pages/conversation, outside this sheet, and under the wait it went on offering the way out to the Export with the drafts still in flight.
- **`DraftReview`** renders inside a card only while the answer is voice-recorded AND still has no confirmed text. Since the wait took over the screen it is the `failed` and post-draft states that show here: a message plus "tentar de novo", or a "sugestão — revise" badge, the editable `source` transcript in the language it was spoken (ENG-370 — the English never shows here), and the confirm button. Once confirmed the card is an ordinary answered card and the block disappears.
- **Confirming every draft at once** (@/ui/pages/report/confirm-all-dialog.tsx). An action above the card list opens a Radix dialog in the house register (cream card over a veil, like @/ui/pages/dashboard's), which says plainly what is being accepted: machine-written texts, becoming the answers, without a per-answer reading. Initial focus goes to "rever uma a uma" — the exit that writes nothing — so a stray Enter never accepts hundreds of machine texts; the accepting button carries text weight, not a primary tile. Four decisions carry the feature:
  - **The single confirm is the only confirmation path.** `confirmInto(state, slot, text)` was lifted out of `confirmDraft`'s `apply` so the batch can fold it N times; a second path would drift from the PT/EN asymmetry below and no test would notice until an artifact came out wrong.
  - **Eligible = has a draft AND an empty answer cell.** The empty cell is what protects the facilitator's own words: typing an answer clears `en__` but leaves `src__` in place, so after she writes, the machine transcript is still sitting beside a now-full cell. Without that condition the batch would overwrite her text with the machine's — the worst thing this feature could do.
  - **One `sessionStore.apply` for the whole batch**, folded with `reduce`. Per-answer `apply` would fire an autosave and a re-render per item, and 467 of them would go down the wire in a queue. The eligibility test is re-read from the accumulating state, not from the render, so the guard holds over the fold.
  - **The result is measured, never assumed.** It counts the pending answers before and after and reports both what was confirmed and what still needs attention (a recorded answer whose transcription failed has no draft to accept and must be written by hand). Counting from the plan instead of the state would report a cheerful "done" exactly when `apply` was silently paused — offline, review mode, another editor's lock — and leave the export refusing with no explanation.
  - The action is absent when nothing is eligible, and the result line is a `role="status"` region registered empty on mount, for the same reason the drafts region is.
- **Redoing answers confirmed from a superseded draft** (`RedoStale`, same file). The generation guard stops the bug recurring; it does not rescue the session where it already happened, because there the cells are full of the stale text and the guard that protects human typing refuses — rightly — to overwrite a filled cell. This is the explicit way through, and it is destructive in a way the bulk confirm is not: that one only fills empty cells, this one **replaces confirmed text**. Hence its own dialog, saying the price plainly, with initial focus on "leave them as they are".
  - **Eligible = the cell is byte-identical to the stored `src__`, and `gen__` is behind the draft the server is offering.** That equality does two jobs at once: an answer with no stored draft is somebody's own text and cannot match, and an answer typed OVER a draft (the `src__` survives beside the cell) cannot match either. "It came from a draft" alone would leave that second door open — which is why there is a test for exactly that case.
  - The text sent up is the server's own, so nearly every request hits the identical-text early return and costs nothing; only the answers the server actually re-transcribed pay a translation.
  - **Bounded concurrency (`REDO_CONCURRENCY`) with visible progress**, and each answer writes its own result as it lands rather than all of them at the end: hundreds of synchronous `PUT`s behind a frozen screen is not a workflow, and a failure partway has to leave a state a second run can finish. The result is counted from what actually came back, so an answer that could not be redone is reported instead of disappearing into a cheerful "done".
- **Both batch decisions share one dialog shell** (`DecisionDialog`). What they have in common is not the look but the initial focus on the exit that writes nothing — duplicating the Radix mechanics would duplicate exactly the line where a slip costs hundreds of answers. The file is still named `confirm-all-dialog.tsx`; it now holds both.
- **The live region is registered empty on mount** and only later carries the summary ("N respostas para revisar"). A `role="status"` created together with its content is not announced by screen readers; it also never moves focus (WCAG 2.2 SC 4.1.3) — the reviewer arrives when they choose. It announces the count only, never the drafts themselves.

### Things to Know

- **Voice duration is real** (ENG-271). The voice row's duration slot (`aria-label="duração da resposta"`) shows the saved recording's length formatted `m:ss`, read from `VoiceRecorder.duration(path)` (@/adapters/voice/types.ts). It falls back to `—` only before the durations resolve or when no recorder is wired.
- **The recorder arrives from the conversation.** @/ui/pages/conversation mounts this station with its own `recorder`; without it every card falls back to "ainda sem resposta gravada" and — since the interview is voice-only — no answer would be audible here at all. The `Transcriber` and the session id travel the same way.
- **The polling loop is `setTimeout`, not `setInterval`** (@/ui/pages/report/use-stt-drafts.ts): with an interval a slow poll does not hold the next one and they pile up. It backs off from 2s to a 10s ceiling, gives up after five minutes into a `failed` phase that offers a retry, pauses entirely while `document.hidden` (the browser throttles hidden timers to ~1/min anyway) and polls immediately on return — that is what makes "leave and come back" feel instant.
- **A late response must not win.** A job started before a re-record can answer after it, so every request carries a stamp (`requestId` ref plus a `paths#attempt` key) and a result whose key does not match the current request reads as "still running" and is discarded. Without it a stale answer would silently overwrite newer state. The phase is derived at render, never written from an effect (the house `react-hooks` rule).
- **Manual typing is always available**, at every phase. If the job fails, stalls, or the port is absent, the card's own answer field still resolves the question — §8.7 requires no dead end, and the machine has no authority anyway.
- **No browser test.** This station has no `Necklace`/canvas geometry, so all tests run in jsdom (`report.test.tsx`): rendering per answer type + role marker, text edits reaching the domain answer store, the facilitator note persisting across a re-mount while staying out of the `.md` (byte-asserted against the real builder), and the draft flow — running/arrived/confirmed, editing before confirming, no draft for an unrecorded question, and the pre-registered live region. The bulk confirmation's suite is mostly **negatives**, because that is where it could do real damage: the dialog changes nothing until it is accepted and nothing when it is dismissed, a hand-typed answer survives it untouched, a draft-less answer is left alone and reported as still pending, and the PT/EN asymmetry is pinned through the real `buildMapReport` output in both languages. The generation, confirm and redo suites follow the same shape — a draft at an unchanged generation is left exactly as a human left it, a filled cell is never overwritten whatever the generation, a refused confirm leaves the answer unconfirmed and says so, and the redo skips both the answer with no draft and the answer typed over one. The `Transcriber` double in `report.test.tsx` **reimplements the route** (identical text returns before the generation check; a stale generation conflicts; otherwise it translates and bumps) rather than spying, because all three of those answers drive the screen. The hook has its own suite (`use-stt-drafts.test.ts`). There are **no export actions on this station**: completing and downloading live in @/ui/pages/export, and its tests own the export gate.

# Noridoc: phrases

Path: @/ui/pages/phrases

### Overview

- The phrase station (ENG-237): "Segmentação — as frases dentro de uma cena" (PRD v2 §8.6, redesign §6.5). Work happens **one productive scene at a time**: the necklace windows down to the active scene ± a margin, the listener anchors phrases inside it, and border-crossings open the visual seam modal instead of blocking.
- A wiring component: it reads the pure @/domain session through the @/ui/state session store, renders the @/ui/organisms `Necklace` (windowed) and `SeamModal`, and dispatches the phrase/seam domain reducers.
- Cream working stage with the "Cena N · <tipo>" title, exactly one instruction line, and exactly one dominant action ("✓ Confirmar esta frase"), per the listener-facing UI rules (§9.2).

### How it fits into the larger codebase

- **The station after Triage.** Stations self-register through the `import.meta.glob('/ui/pages/*/index.tsx')` registry built in @/ui/app/registries.ts, so the default export in `index.tsx` is mandatory — it is the registry value, keyed by the directory name `phrases`. @/ui/app/App.tsx's `KEY_TO_MODE` maps `phrases` to the domain `phrases` mode; the app shell renders this station when the session mode is `phrases`.
- **Wiring layer.** Per @/.dependency-cruiser.cjs, @/ui/pages may import @/domain, @/ui/state, @/ui/organisms, @/ui/molecules, @/ui/atoms, @/ui/tokens and adapters. It also reuses three pure helpers from the sibling station @/ui/pages/cut (`playActionOn`, `sceneColor`, `sceneLabel`) — same anchoring ceremony, no duplicated cardinal.
- Reads session state via `useSessionStore` and writes only through `sessionStore.apply` (see @/ui/state/docs.md), so the store's editability gates (online/review/lock) can silently pause an anchor/move/boundary-drag without losing in-memory state.
- Advancing dispatches `confirmFrasesDone` (@/domain/phrases.ts), which — after the empty-scene soft warning — either enters the next productive scene or moves the guided flow to Conversation (`mode='conversation'`).
- **A `kind: 'mapeamento'` result also closes a BLOCK (ENG-651):** the station then calls the optional `onBlockClosed('segmentacao')` prop. It never recomputes which scene was the last productive one — `confirmFrasesDone` returning `mapeamento` instead of `next-scene` IS the domain's answer, and the station only relays it. The screen belongs to the shell (@/ui/app/docs.md).
- The itinerant `Player` (@/ui/app/player-slot.tsx, @/adapters/audio) is injected by prop, not constructed here — see the audio seam below.

### Core Implementation

- **`Phrases({ player })`** (@/ui/pages/phrases/index.tsx): subscribes `session` from the store; renders `null` until a session with an active productive scene exists. A single `useMemo` keyed on `session` derives the active scene (`activeScene`), its span, the scene's locked phrases (with their global index), and the necklace's `segments`/`lockedEndBeads` — one memo so per-frame `playbackHead` updates never recompute the field (the necklace's no-rerender imperative lighting).
- **Header + framed stage** (realigned to the Protótipo): the "Cena N · tipo" title now carries a small scene-tinted swatch (`sceneColor`, reused from @/ui/pages/cut/cutting.ts) next to the text; the whole necklace stage sits inside a dashed 26px-radius frame (`phrases.css`), and the necklace uses the `SIZE_SEG` preset (30px beads — the largest of the three presets, since this station is where phrase precision matters most).
- **Windowed necklace** — the `window` prop is the active scene span; the organism draws the dashed awake band and dims/omits beads outside scene ± `max(3, round(2/beadSec))` (the margin lives in `resolveWindow`). Locked phrases tint the cord via `phraseColor` (cycles `phrasePalette`); their end beads render square.
- **Click model — locked phrases are heard, free beads are cut (ENG-296; full rules @/docs/segmentation-rules.md — IDENTICAL to the scene).** `onBeadPointerDown` asks `lockedItemAt(scenePhrases, bead)` **first**: a bead inside an already-**confirmed** phrase plays **FROM the tapped bead** to the phrase end (`player.toggle('<prop_id>:<bead>', bead, span.e)`, rule 4; per-bead key jumps/pauses) and returns, leaving the cut alone. Only phrases of the **active scene** count — the only ones in the necklace's window. Otherwise it delegates to `clickBead` (@/domain/selection.ts) and plays via `playClick(player, play, scSpan.e, head)`. The phrase follows the same three beats as the scene: the **first** click marks the START and the SCENE runs from it, the **second** closes the phrase, and from the **third** on the nearest boundary moves (`adjust`) without interrupting audio already running inside the resulting stretch, otherwise playing only the stretch that changed hands — tapping a boundary that does not move replays the whole stretch (`range`). Both layers now open with no selection, so the reference's scene/phrase asymmetry (only scenes had `primePart`) no longer applies. `onEdgeHover` goes through `playHoverEdge` (silence only). Dragging the boundary goes through `playDragDelta` (same as the scene): the stretch that changed hands, once, at the end of the gesture. `onHeadTap`: keyless `run`/`range` playbacks `stop()`; a confirmed-phrase playback (keyed) pauses/resumes via the active key.
  - **Why here and not in `clickBead`:** same reason as cut (see its docs.md) — the reducer is a frozen 1:1 port that clamps the click to the frontier and would consume the next phrase's pre-anchoring. The click model deliberately has two homes; a third station would be the signal to move the rule into the domain instead.
  - **`onHeadTap` (ENG-297's guard, needed here too):** this station has `onEdgeHover` → `playEdge`, which is **keyless** (`playRange` clears `key`). Without asking the key first, the glowing bead during an edge preview would re-toggle a foreign key and **restart** the phrase for someone tapping to stop. Keyless → `stop()`; own key → pause.
- **Confirm this phrase** — the dominant action (`data-role="primary-action"`) dispatches `confirmFrase(state, current.index)`, whose result is a discriminated union: `error` (shows the domain copy), `border` (opens the seam modal with the offer), `locked` (applies the new state), `noop`. It renders while `activeAnchor(session)` exists (always true while phrasing a scene).
- **The review moment (`covered`, owner decision):** once the active scene's locked phrases cover it end to end (the highest locked phrase's end bead equals the scene span's end), the station collapses to one headline (`phrases.reviewHeadline`) plus one action (`review.continue`, shared with @/ui/pages/cut and @/ui/pages/triage) that dispatches the same `confirmFrasesDone` — so a fully-covered scene never shows the empty-scene warning, since coverage already proves at least one phrase exists. A scene with sparse phrases (gaps still open) keeps the PRD's instruction/confirm-phrase/"Pronto com esta cena →"/"Já segmentei todas as cenas →" flow untouched, because sparse phrases are a deliberately allowed outcome of the frozen domain — the station never forces full coverage.
- **Seam modal** (@/ui/organisms `SeamModal`): fed the domain `BorderOffer` plus the scene and the immediate neighbor of the crossing side (`nextNeighbor`/`prevNeighbor`, tinted by `sceneColor`). `Mover a borda até aqui` → `moveBorder(state, offer)` (slides the shared seam, then locks); `Reancorar dentro da cena` → `reanchorFrase` (clears the selection); `Voltar à Triage` → `setMode('triage')`. Move runs against the same store state that produced the offer (unchanged while the modal is open).
- **Locked phrases** render as a `BeadStrip` (@/ui/molecules) below a hairline — one bead per phrase, ordered and coloured by position in the scene, with the spelled-out "Frase N" only in the capsule (ENG-388; the wrapping `ScenePhraseChip` row it replaced made a long scene's footer shout every phrase's actions at once and pushed "Pronto com esta cena" off screen). Tapping a bead opens **one** capsule; no `sub` is passed because a duration would put a digit on the listener's screen (§9.2), and there is still no ▶ (ENG-291: the beads play the phrase). The page owns the selection and it carries the `scope` it was made in (`slug + manifestId + mode + activeSceneId`), so opening/resuming another session or changing mode invalidates it by construction — no effect, no cascading render — while Remover and the two scene-navigation gestures (`done`, `back`) clear it explicitly, so arriving at a scene never inherits an open capsule (the domain reassigns `prop_id` by lowest-free, so a surviving key could point at a different phrase). Remover composes `absorbNextFrase(removeFrase(...), part_link, removed.span.s)` — `removeFrase` is pure/reference-faithful (the golden replays it), and the **next** locked phrase of the SAME scene absorbs the freed gap (stretches its start back; #3, owner decision, symmetry with the scene chip). Reabrir/⚑ revisar were removed in ENG-342 — post-lock boundary adjustment is now dragging the phrase's END on the necklace (`dragPhraseBoundary`, via the necklace's `dragHandles`/`onDragBoundary`, composed with `primeFrase` so the pending phrase re-anchors on the new frontier — else, with the prior phrase covering the necklace end, the frontier sits past the grid and the next click closes beyond the story). Only the END gets a handle — strictly like scenes (owner decision, cut↔phrases symmetry): dragging it is **Pac-Man/tiled** — the NEXT phrase of the same scene follows the boundary in both directions (its start becomes `newEnd+1`), so shrinking never leaves a gap (the next grows to fill) and growing pushes it; the last phrase (no next) grows/shrinks freely to the scene end. A phrase's start is the seam, moved only by dragging the previous phrase's end, never directly. `phraseLabel` reuses cut's tested cardinal ("Cena N" → "Frase N") so the screen stays digit-free. Full rules: @/docs/segmentation-rules.md.

### Things to Know

- **Primary button** reads "Pronto com esta cena →", or "Já segmentei todas as cenas →" on the last productive scene (`sceneIndexOf` vs `productiveScenes.length`) — only while the scene isn't `covered`; once covered, both collapse into the single `review.continue` button (see Core Implementation), which still dispatches `confirmFrasesDone`.
- **Empty-scene soft warning:** leaving a scene with zero locked phrases surfaces "Esta cena ficou sem frases. Clique de novo para seguir mesmo assim." once (the `warnedEmptyScene` marker is UI-local state); a second click proceeds. Reference-faithful.
- **"← Voltar"** goes to the previous productive scene (`enterScene`), or to Triage from the first (`setMode('triage')`) — a port of the reference's `frasesBack`.
- All validation copy comes verbatim from `FRASE_ERROR_COPY` / `FRASES_EMPTY_WARNING` (@/domain/phrases.ts) — never re-authored in the UI; shown in a `role="alert"` line. The only digit any listener sees is the facilitator bead number interpolated into the "phrase starts before bead X" message (§9.2 carve-out). Being domain copy, all of it stays **PT-BR under an EN UI**; the station's own copy and the seam modal translate (@/ui/i18n).
- **The audio seam is the extension point.** `player` defaults to `null`; with no player the click model computes state but skips playback, and no engine is constructed here. Extend audio through this prop.
- Chip-entry motion (@/ui/pages/phrases/phrases.css) is guarded by `@media (prefers-reduced-motion: no-preference)`; bead lighting motion lives in the atoms, already guarded there.
- Tests split by suffix: `wiring.test.ts` and `phrases.test.tsx` run in jsdom; `phrases.browser.test.tsx` runs in real Chromium for the coordinate click model against real windowed necklace geometry (jsdom has zeroed layout).

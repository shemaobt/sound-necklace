# Noridoc: login

Path: @/ui/pages/login

### Overview

- The Login station (ENG-245, restyled to the Shemá v2 opening in ENG-278): the facilitator entry (PRD v2 §7.1). A **two-panel opening** — left, a ceremonial brand panel (`ColarIcon onDark` from @/ui/tokens over the olive `--cds-olive` field — the site mark replaced the white `ShemaIcon` here; `onDark` is what lifts its cord and end beads off the olive) carrying the verse "Assim na terra como no céu.", a tagline, and the privacy line "Nada do áudio sai deste computador."; right, the calm cream form (`--cds-cream`) with eyebrow "Entrar", heading "Bem-vinda de volta.", subtitle "Continue de onde vocês pararam.", the Usuário/Senha fields, and a telha (`--cds-telha`) submit that reads "Entrando…" while auth is pending. Success routes to the dashboard; a rejected credential shows one PT-BR guidance line and keeps the login screen. All of its copy comes from @/ui/i18n — it is the first screen a facilitator sees, so it is also the first proof the language choice survived the reload. The route owns its own header (see @/ui/app/docs.md's `ownsHeader`), so the PT/EN toggle is never on this screen; it lives in @/ui/pages/settings, reachable only from the dashboard.
- **The Shemá returned, as a corner watermark, not the hero.** PR #181 (commit 61b00ee) moved the site mark into the hero panel above and relocated the session-screen watermarks (e.g. @/ui/pages/listen/docs.md's `.cds-listen-watermark`) into the bottom-right corner, but left the login with no watermark at all. This pass restored one, in the same register: an `aria-hidden` `ShemaIcon colorway="telha"` bleeding out of the page's bottom-right corner, `pointer-events: none`, opacity 0.05. `telha` and not `branco` because that corner is the cream form panel, not the olive hero — on the olive the colorway would have had to be `branco`. The wrapper does the clipping (`position: absolute; inset: 0; overflow: hidden`) rather than `.cds-login` itself, whose own `overflow: hidden` would clip the form — the submit button first — in a short window; @/ui/pages/setup/docs.md documents the same arrangement for Setup, for the same reason. `.cds-login-hero` and `.cds-login-card` are `position: relative` so they paint above the positioned watermark. **The mark is meant to be seen** (owner call): roughly 61% of its ink stays on screen at every viewport, with only the corner bleeding off. It bleeds off BOTH edges deliberately — the Shemá drawing fills only ~61% of its own viewBox width, so a smaller horizontal offset leaves it floating with a gap on the right, which reads as a loose card rather than a watermark. The accepted price, measured rather than assumed: in a window under roughly 700px tall the mark passes behind the password field and the "Entrar" button. It never steals the click (the wrapper is `pointer-events: none`, and a hit test at the button's centre returns the button at every viewport) and the controls are opaque, so they cover the mark instead of blending with it.
- `Login({ auth })` — the `AuthProvider` port (@/adapters/api) arrives **by prop** in tests; in production it resolves the fixture singleton shared with the dashboard (@/ui/pages/dashboard/ports.ts), so the auth the login logs into is the SAME instance the dashboard watches for expiry.
- The submit is a native `<form>` + `<button type="submit">` (Enter-to-submit) styled in `login.css` — deliberately NOT the `Button` atom (which is `type="button"` and cannot submit).
- **Reconciliations prototype ↔ contract** (CLAUDE.md precedence rule 1 — data wins over the prototype's look, whose source is @/docs/design/README.md): the field stays "Usuário"/`username` (the auth contract keys on `username`; fixture/e2e use `facilitadora`/`admin`) rather than the prototype's "E-mail"; the prototype's `noop` "Criar conta"/"Esqueceu a senha?" links are omitted (no MVP flow); the brand mark is the inline `ColarIcon` because there is no svg-asset **import** pipeline for marks React renders — not for the prototype's `logo-branco.svg` wordmark, not for `pattern-tile.svg`, and not for `docs/design/website-icon.svg` either, which is why that mark is ported as inline JSX rather than imported. The tab icon is a different case, added later: @/public/favicon.svg is a static file, referenced by URL from @/index.html and never imported by the bundler, so it needed no such pipeline — see @/ui/app/docs.md. Focus outline and `prefers-reduced-motion` are inherited from the global @/ui/tokens/base.css floor — no per-file duplication.

### How it fits into the larger codebase

- **Routed station.** The shell (@/ui/app/App.tsx) renders station key `login` for `/login` via `import.meta.glob('/ui/pages/*/index.tsx')` (@/ui/app/registries.ts), so the default export in `index.tsx` is mandatory. Navigation uses the minimal History-API router (@/ui/app/router.ts) — success calls `navigate('/dashboard')`.
- **System-boundary error handling.** Only `AuthError` (credential rejection) becomes the guidance line; any other failure bubbles (not masked). The in-memory app state is never touched here — session hygiene (§7.1/§12) is the `AuthProvider`'s job.
- **Fixture credentials.** `FixtureAuthProvider` accepts a known username (`facilitadora`/`admin`) + any non-empty password; no credential literal lives in the repo.

# Noridoc: dashboard

Path: @/ui/pages/dashboard

### Overview

- The Sessions dashboard (ENG-245, redesigned to the Shemá v2 prototype in ENG-278): the post-login home (PRD v2 §7.2). Lists ALL the facilitator's sessions as a **grid of story cards** — story name, `slug · project`, status, last-modified, and a glanceable progress cover; resumes an in-progress session straight into its saved step; **renames a story's display name** (ENG-281); **deletes a story for good, after asking** (ENG-281); and starts a new story.
- `Dashboard({ auth, store })` — the `AuthProvider` + `SessionStore` ports arrive **by prop** in tests; in production they resolve the fixture singletons in @/ui/pages/dashboard/ports.ts.
- **A full-bleed surface with its OWN header** (brand + the authenticated user + "Sair"), like @/ui/pages/login: the shell suppresses its utility header on both routes, so this page owns the top of the screen.
- **There is no artifact download here any more** (ENG-689, scope cut 1/4): the app stopped generating the three documents (`manifesto-contas.json`, `retorno-ancoragem.json`, report `.md`) when it stopped reaching Export, and a menu entry offering yesterday's artifacts would promise something the product no longer does. The card's actions menu (`ActionsMenu`, see Core Implementation) now carries only Renomear/Apagar, on every card regardless of status.
- **Renaming moves the display name and NOTHING else** (ENG-281): the card's actions menu → the `dashboard.renameDialog` dialog, prefilled and pre-selected with the current name → `store.rename(id, trimmedName)` → the list is re-fetched. The `story_slug` is untouched by the request: it names the story's stored resources server-side, so a rename that carried the slug would silently misfile them — a rule that predates and outlives ENG-691's removal of the three artifacts @/contracts used to build under that slug (@/contracts/docs.md). The dialog's own body line says so (ENG-700 reworded it from "os documentos" to "o nome com que a história está guardada no projeto", since there are no documents to speak of any more — the reason for the rule is unchanged, only the noun was wrong).
- **Deleting is a hard delete, guarded by a question** (ENG-281): the card's actions menu → the `dashboard.deleteConfirm` dialog → `store.remove(id)` → the list is re-fetched. The confirmation **names the story and enumerates what goes with it** — the cuts and the classifications — because a bare "are you sure?" would not let the facilitator notice they opened the wrong card's menu. It used to also name "the voice recordings go with it"; ENG-700 dropped that clause because there are no answers and no recordings left to delete (they left with the Conversa, ENG-689/ENG-691).

### How it fits into the larger codebase

- **Routed station.** The shell (@/ui/app/App.tsx) renders station key `dashboard` for `/` and `/dashboard` via the `import.meta.glob` station registry. Resume/open call `navigate('/session/:id')`; the shell rehydrates the persisted session and resumes at the saved step (§7.3, `useSessionHydration`). "Nova sessão" calls `navigate('/setup')`, which the shell routes to the Setup station (ENG-272).
- **Presentational organisms, props only.** Renders @/ui/organisms/session-list (status + last-modified + progress glance; the page maps `SessionSummary` → `SessionCardData`, formats the date, and derives the station glance from `progress.current_step`) and composes each card's actions menu itself. Direct import (the organisms barrel is frozen).
- **Language-aware formatting** (ENG-279, @/ui/i18n/docs.md). The station labels of the glance are dictionary keys resolved here, and `formatWhen(iso, locale)` takes a locale (`pt-BR` default, `en-US` under an EN UI) so `toLocaleString` dates follow the UI language. The labels are the SAME `stations.*` keys the shell's progress band resolves (@/ui/app/stepper-model.ts emits the `labelKey`), so the card and the chrome can never disagree about a station's name.
- **The server still knows steps this app no longer has** (ENG-689). `PAST_THE_END` maps the two lifecycle steps `adapters/sessions` still reports for a completed session — `conversation` and `save`, both frozen-layer concerns this slice deliberately did not touch — onto the LAST of the FIVE stations this glance now lists (@/contracts's `SessionStep` type — a frozen-layer contract — has no `review` entry, so those two past-the-end steps land on Review instead, the fifth station added in ENG-725); translating there rather than in the adapter keeps that layer untouched. A session whose saved `current_step` is one of those two glances as fully done, not as stuck on a station that no longer exists.
- **Auth expiry (§7.1).** Subscribes `auth.onAuthExpired(() => navigate('/login'))` — routes back to login **without touching the store** (the caller's in-memory state is preserved so re-login resumes). Shared-singleton `ports.ts` makes the login's auth and the dashboard's the same instance. The app root (@/ui/app/App.tsx `useAuthExpiry`) subscribes the SAME singleton too, so expiry also routes to login from inside a live `/session/:id` (ENG-277); the dashboard keeps its own subscription harmlessly (both just navigate). "Sair" is the explicit counterpart: `auth.logout()` then `/login`.
- **`ports.ts`** — `defaultAuth()` delegates to the **app-global** `appAuth()` singleton (@/ui/app/auth-adapter.ts, ENG-277), so Login, Dashboard and the session root all share ONE `AuthProvider` — a single expiry trigger reaches every surface. `defaultSessionStore()` returns the **app-global** `appSessionStore()` (@/ui/app/session-adapter.ts, ENG-272), the same store Setup writes to, so a session created in Setup appears in this list. Env-based real-adapter selection is composition-root wiring (ENG-247), out of scope here; the defaults are production-only and intentionally untested (tests inject the ports).
- **The shell hands over the header** (@/ui/app/App.tsx `ownsHeader`): `login` and `dashboard` render NO @/ui/app/header.tsx. Both the shell header and this page's header carry an `<h1>Colar de Sons</h1>` and a `<header>` banner, so stacking them would duplicate both. Consequence: the shell's sound toggle does not exist here — this is a facilitator surface with no playback (the stations keep it).
- **The page does all the arithmetic the organisms refuse to do**: `formatWhen` turns `last_modified` into a display string, and `progressOf` turns the saved `current_step` into a `{ progress, label }` pair. `toCard` maps a @/contracts `SessionSummary` onto the organism's `SessionCardData`, including the status translation (the wire uses underscores, the organism's `data-status` uses hyphens) — a per-status map, so adding a lifecycle value means adding one entry here, one in @/ui/organisms/session-list and one dictionary key in @/ui/i18n.

```
FixtureSessionStore ─ list() ──▶ SessionSummary[] ─ toCard ─▶ SessionCardData ─▶ SessionList
        │                                                    (progressOf/formatWhen, PAST_THE_END)
        ├─ rename(id, name) ◀── RenameDialog ◀── menu entry (any status) ─ then list() again
        └─ remove(id) ◀── DeleteConfirm ◀── menu entry (any status) ─ then list() again

FixtureAuthProvider ─ currentUser() ──▶ own header    onAuthExpired/logout ──▶ /login
```

### Core Implementation

- **`progressOf(step)` is the §7.2 "glanceable progress indicator"**, reduced to two values the organism can render: `progress = (i + 1) / STEPS.length` over the five `STEPS` (ouvir → cortar → triage → frases → review, ENG-725 added the fifth) and an accessible label naming the station and its position. `PAST_THE_END` steps clamp to the last index before this division runs, so a completed session's cover shows fully lit rather than pointing past the end of the array. An unrecognized step clamps to the first station (`Math.max(0, findIndex)`), so a bad DTO renders a card instead of throwing.
- **Own header:** the site mark (@/ui/tokens `ColarIcon` — the drawn necklace, which replaced the `telha` `ShemaIcon` here so both header bars carry the same mark; its cord and end beads are repainted from `--cds-ui-body-ink` in `dashboard.css`, because they are the dark part and this surface follows the theme), `<h1>Colar de Sons</h1>`, then the user block — rendered ONLY when `auth.currentUser()` is non-null — with the `username` as text plus an `aria-hidden` avatar holding its first initial (decorative: the username is already the accessible text), and the ghost "Sair" button.
- **Body headings:** an "Arquivo oral" eyebrow, `<h2>Suas histórias</h2>`, and a story count (`1 história` / `N histórias`) rendered only once the listing resolves. Digits are fine — facilitator density (§9.2 constrains listener surfaces only).
- **Loading vs empty are different shapes.** While `sessions === null` a `role="status"` line says "Carregando as sessões…". There is no empty-state paragraph anymore: an empty list renders the grid containing only the "Comece uma nova história" card, which IS the empty state and the new-story affordance at once.
- **The card's actions menu (`ActionsMenu`, ENG-305 → ENG-281 → ENG-689):** a Radix Popover behind a `⋮` trigger whose accessible name **carries the story** (`Ações em <story>`) — two cards in the grid mean two triggers, and "Ações" alone would not say which. It hangs on **every** card at every status: renaming and deleting are the only two entries left, and both are available at any moment (the download entry that used to be conditional on `status === 'completed'` left with the artifacts).
- **`CardDialog` is the shared shell of the two card dialogs** (ENG-281): veil, cream card, a title that **names the story**, one explanation line, the fixed slot for a refusal, and the rule that dismissal (ESC, overlay) is refused while the call is in flight — a refusal that arrived after the dialog vanished would have nowhere to land (§9.4: never a silent no-op). Initial focus is the caller's, via a `focusOnOpen` callback, because the safe answer differs: the delete dialog focuses **"Manter a história"** so a stray Enter never destroys; the rename dialog focuses and **selects** the field so a typo can be overwritten immediately. It is deliberately NOT a general-purpose dialog component — two uses, one page.
- **`RenameDialog` (ENG-281):** a `<form>` inside that shell, so Enter saves. The name is **trimmed before sending**, and an empty (or all-spaces) name leaves the save button `disabled` — the server refuses it too, but the facilitator should not need a round trip to learn it. The same `disabled` covers the double submit twice over: a repeated click and a repeated Enter both die on it, since implicit form submission needs an enabled submit button.
- **Only the write decides whether the write happened.** Renaming and deleting are each two round trips — the write, then `list` — and the shared `refresh` callback lives **outside** both `try` blocks on purpose: if `list` fails after a successful `remove`, calling that "não consegui apagar" would send the facilitator to retry something already done, whose retry hits a 404; the same reasoning holds for a rename that landed. A failed refresh raises the page's own `listError` line instead ("recarregue"), which is what actually went wrong.
- **Both dialogs translate a refusal the same way.** A `LockLostError` carrying a holder becomes "`<holder>` está com esta história aberta agora", anything else becomes that dialog's generic failure line; **either way the dialog stays open with a `role="alert"` and the card is untouched** (§9.4 — errors guide, never punish). The popover is NOT closed by hand: Radix dismisses it when the dialog takes focus.

### Things to Know

- **Prototype ↔ contract reconciliations (ENG-278).** CLAUDE.md precedence: look/layout follows the prototype, but behavior and data follow the PRD/contracts — so where the prototype implies data that does not exist, the data wins.

  | Prototype (Shemá v2)                                        | Shipped                                   | Why                                                                                                                                                                                                                                                                                        |
  | ----------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | Kebab menu: renomear / duplicar / excluir / só para revisão | Delete shipped (ENG-281); duplicate never | `store.remove` landed in ENG-281's slice A, so **excluir** is real — behind a confirmation, available at any status. **Duplicar** has no port method and no §7.2 line, and stays out. **Renomear** is its own slice. "Só para revisão" is a per-open mode (§7.3/§8.10), not a card action. |
  | Full name + e-mail ("Marcia Alencar / marcia@shema.org")    | `username` + initial                      | `AuthUser` is `{ id, username, roles }` (@/adapters/api/types.ts) — the prototype's identity is mock data; nothing is invented.                                                                                                                                                            |
  | A third status, "Em revisão"                                | Not ported                                | The contract's statuses are `in_progress` / `completed` (@/contracts/api.ts). The prototype's "Em revisão" means the read-only editing mode, which is a per-open state (§7.3/§8.10), not a session status.                                                                                 |
  | Card shows the slug only                                    | `slug · project`                          | §7.2 explicitly requires project on the card.                                                                                                                                                                                                                                              |

- **The download entry (ENG-305, ONE menu action saving all three documents since ENG-281) is gone (ENG-689):** the app no longer reaches Export, so nothing is ever generated for the dashboard to hand back. @/ui/organisms/artifact-cards, the organism that used to render those three documents, was deleted along with the Export/Conversation/Report stations that composed it.
- **The old chrome is gone**: no `<h1>Minhas sessões</h1>` (the h1 is now the brand, and the page title is the h2 "Suas histórias") and no header "Nova sessão" button — the grid's dashed card replaced it. Tests and e2e that key on those strings must target the new ones.
- **A story named "Em andamento" collides with the status chip label** in test queries (the chip text is now "Em andamento"/"Concluída"). The page's own tests renamed the fixture story for exactly this reason.

# Noridoc: ui/state

Path: @/ui/state

### Overview

- The domain-state bridge (ENG-224): thin Zustand stores that wrap the pure @/domain `SessionState` and the app-global UI flags, so the screens read/write session data through hooks without any component ever mutating domain state directly.
- Four stores, all exported from @/ui/state/index.ts: @/ui/state/session-store.ts (the session plus its editability gate flags), @/ui/state/app-store.ts (the global `muted` sound toggle, surviving session changes), @/ui/state/progress-store.ts (the view-only fact the whole-story bar needs beyond `SessionState`) and @/ui/state/goal-store.ts (today's goal). The `recording` mic flag that used to live in `app-store.ts` was removed in ENG-689: its only producer was the interview recorder, so with the interview gone the flag could never turn true again.
- The guiding split: @/domain decides WHAT changes; this layer decides WHETHER a change is allowed to happen.

### How it fits into the larger codebase

- Sits between @/domain and the wiring layer (@/ui/pages, @/ui/templates, @/ui/app). Per @/.dependency-cruiser.cjs it may import @/domain (types + reducers) and zustand, but NEVER adapters — persistence arrives as an injected `autosave` port instead. This ban is a required CI boundary check.
- Consumed by @/ui/app: `App` reads session/review/lock/online/muted through `useSessionStore`/`useAppStore` and reflects the connectivity port into `setOnline`. The review banner and the connection gate derive from these flags, as does the station model that names the current step in the progress band (@/ui/app/stepper-model.ts). `setMode` itself is dispatched from inside the stations, never the shell (ENG-668 retired the shell's only caller, the fio-de-contas dots).
- Holds the three editability gates spread across the PRD: review mode (§8.10), the single-editor advisory lock (§7.3), and the online-only gate (§13). The domain gate math (`modeLocks`, whole-story/scene gates) stays in @/domain; this store layers the human/collaboration/network gates on top.

### Core Implementation

- **`createSessionStore(deps)` factory + `sessionStore` singleton** (@/ui/state/session-store.ts): a Zustand vanilla `createStore` holding `session: SessionState | null` plus `review`, `lock`, `online`. Every mutation flows through a single `apply(reducer)` entry point.
- **`apply(reducer)`** runs the reducer ONLY when `canEdit()` is true, then calls the injected `autosave` port. Otherwise it is a silent no-op — offline, review, and a foreign lock PAUSE editing without clearing in-memory state (nothing typed or anchored is lost).
- **`canEdit()` invariant:** `online && !review && lock === null && session !== null` — the exact predicate every edit path checks.
- **Lock forces review:** `setLock(holder)` sets the lock and turns `review` on together; `unlock()` clears review ONLY when no lock is present, so a session another editor holds cannot be unlocked into edit mode.
- **`autosave` is an injected port** (`SessionStoreDeps`), defaulting to a no-op. This is why the layer can persist without importing adapters. The `sessionStore` singleton is created with the default no-op; the shell wires the real port at runtime via **`setAutosave(fn)`** (ENG-273) — the singleton is imported before any adapter exists, so a runtime setter (not a constructor arg) is how @/ui/app connects continuous persistence while ui/state stays adapter-free. Passing `undefined` unwires it. Each `apply` then calls the current port with the freshly-computed state.
- **`createAppStore` + `appStore`** (@/ui/state/app-store.ts): the global `muted` sound toggle, kept separate from the session store because it outlives any single session and enters no exported artifact.
- **`createProgressStore` + `progressStore`** (@/ui/state/progress-store.ts, ENG-648): the fact the whole-story progress bar needs that `SessionState` does not carry — how many beads of the story have actually been HEARD (published by @/ui/pages/listen). It is not a decision, it never enters an artifact and it does not belong in the session DTO; it lives in memory and dies with the tab. It only GROWS (`Math.max`, non-finite input discarded): the whole-story bar does not walk backwards because playback returned to the start. `reset()` is per session and is called by @/ui/app's `SessionStations` on mount. The store used to carry a second fact — artifacts DOWNLOADED, published by the now-deleted Export station — removed in ENG-689 along with `noteDownloaded`.
- **`createGoalStore` + `goalStore`** (@/ui/state/goal-store.ts, ENG-653): today's goal — how far the pair mean to get in this sitting. One of five fixed options (`TODAY_GOALS`: `twoScenes`, `fourScenes`, `triage`, `phrases`, `wholeStory`) or `null`, which is a valid state and the default. A sixth option, `twelveTalks`, left with the interview in ENG-689. `chooseGoal(g)` toggles: choosing the goal already chosen CLEARS it (the prototype's `setMeta`). It lives here, and deliberately NOT in the session DTO, for two reasons: `contracts/` is a frozen layer and nothing here reaches an artifact (the goal is an agreement about the day, not a decision about the story), and the screen that sets it (@/ui/pages/setup) runs on a different route from the screen that draws it (@/ui/app/story-progress.tsx) — at the moment of choosing, the session does not exist yet. There is **no `reset()`**: zeroing it on session mount would erase the choice just made on Setup. What re-arms per session is the celebration's own mount, via the shell's `key={sessionId}`.
- **The session clock** (@/ui/state/session-clock.ts): the session's NET working time. It used to be shown once, on the Export completion screen; that screen was deleted in ENG-689, and nothing in `ui/` reads `freezeClock`'s frozen total any more — the pulse (`useSessionClock`) still runs, mounted from @/ui/app/App.tsx, because @/ui/state is a frozen-adjacent layer this slice did not touch. "Net" was defined nowhere — not in the PRD, not in the MVP plan — so it is the simplest reading that holds up: time with the session open and the tab visible, minus any gap longer than `IDLE_GAP_MS` (5 min) between one pulse and the next. That discount is the whole difference between "net" and "wall clock": closing the tab, switching windows for half an hour, the machine sleeping or the day turning over do not become work. `tick()` is the pure rule; `startClock`/`markActivity`/`freezeClock`/`resumeClock` persist it; `useSessionClock(sessionId)` is the pulse and is mounted by @/ui/app/App.tsx, the only place that knows which session is open. Storage is `localStorage` under a namespaced, versioned key, every access in try/catch (the tutorial-popup precedent).

### Things to Know

- **The clock measures presence, not keystrokes.** Deliberately no activity tracking (keys, clicks, pointer): the house rule bans telemetry on listener behaviour, and a facilitator listening to a whole trecho without touching anything is working. Having the session open and in front of you IS the signal. It also never leaves the browser: it never entered an artifact even before ENG-691 removed the three documents that could have carried a time field, and it does not enter the session-state DTO either (@/contracts/docs.md).
- **Freezing is what makes the number honest.** Completion calls `freezeClock` and the Export renders the frozen total from state; without it the chip would creep upward while the completion screen sat open. "Destravar para editar" calls `resumeClock(now)`, so the pause between the two sittings is not billed.
- **Pausing is not clearing.** Offline/review/lock make `apply` a no-op but leave `session` intact; the mechanism deliberately preserves state so a dropped connection or a review toggle never loses work.
- The store never imports adapters by design — if you need persistence, inject it through `SessionStoreDeps.autosave`; do not reach for the SessionStore adapter here.
- Zustand 5 selector trap (see @/ui/docs.md): selectors returning fresh references need `useShallow`; the `useSessionStore`/`useAppStore` hooks take a plain selector via `useStore`.
- `EditorLock` is an advisory presence marker — its mere presence means editing is suspended and cannot be unlocked; it is surfaced read-only by @/ui/app/review-banner.tsx. `holder` is `string | null` and is written from two directions: @/ui/app/use-editor-lock.ts (acquire/renew sees a foreign holder, or its renew deadline fires) and the `onLockLost` wiring in @/ui/app/session-adapter.ts (an autosave refused with 409 SESSION_LOCKED). A name means another editor's session is open; `null` means the lock is present but nobody can be named — the renew deadline expired without an answer, or the 409 body carried no `holder_name` — so this client can no longer vouch for editing. Both cases lock out editing; the banner shows a different message for each.
